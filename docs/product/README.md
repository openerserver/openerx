## 1. 目录用途

这个目录只放偏产品、商业和对外表达的文档。

这里的文档可以用于产品讨论、运营准备、销售对齐和管理层决策，但默认不作为“当前代码实现真值源”。如果问题是“系统现在到底怎么实现”，应优先回到 root `docs/` 下的架构、runtime、task-domain 和 workflow 文档。

## 3. 阅读边界

1. 这类文档允许保留较多目标方案、包装策略和对外表达草案，不要求全部都与当前代码一一对应。
2. 如果文档涉及 runtime、schema、审批、预算或实现边界，应把这些内容视为“产品口径引用”，并以对应的技术文档为准。
3. 后续若其中某篇成为稳定现行依据，应再补统一头信息，而不是继续只靠目录位置表达状态。

## 4. 一句话边界

如果问题是“OpenerX 应该怎么讲、怎么卖、怎么分层、怎么包装”，先看这里；如果问题是“代码现在怎么实现”，回到根 `docs/` 的技术目录。
