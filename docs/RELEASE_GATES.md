# 开源桌面版发布门禁

本仓库的正式发布范围是 Windows x64、macOS arm64/x64 桌面客户端。源码可公开与正式签名发行是两个阶段；构建成功不能替代平台验收、许可审核或发布批准。

## 必须完成

1. 干净安装、公开文件及可达历史检查、类型检查、测试和依赖检查。
2. 默认 BYOK 的真实请求、流式回复、停止和失败恢复；自动化、Skill 和记忆设置的真实包启动与重启回归。
3. 三个桌面目标的原生签名/公证、安装、升级和回滚；保留用户历史、成果与凭据。
4. 项目目录选择、断开、重连、上下文权限和升级后保持；不从同步元数据恢复设备权限。
5. 冻结版本的性能、隐私、安全、无障碍与支持材料审核。
6. 第三方许可例外审核、更新签名配置、回滚演练和明确发布批准。

`tests/v2/golden/m8-gate-status.json`、`m9-gate-status.json` 与 `personal-projects-gate-status.json` 记录当前公开范围的状态，`npm run release:gate:v2` 在证据或批准缺失时应失败。新增证据必须对应实际执行，不得手工把未完成项目改成通过。

可选平台服务仍应运行自身合同/隔离测试，但生产支付商户、移动商店和手机真机验收不在这个桌面发布清单中。企业仓库保存原来的完整业务/移动验收基线，企业发行需独立审查。

## 发布与恢复

冻结可恢复提交，先准备应用归档、校验和与签名，再发布经过验证的更新清单。更新私钥和原生签名凭据只存在于受保护的发布环境。发现数据丢失、授权绕过、凭据泄露或签名异常时停止推广；修复通常以更高补丁版本向前发布，不关闭版本或签名校验，不删除用户数据。

GitHub 配置与操作步骤见 [发布清单](PUBLISHING.md)，当前未完成事项见 [验证记录](RELEASE_VALIDATION.md)。
