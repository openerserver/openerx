# 用户系统验收 Runbook

本文档供团队成员按步骤完成用户系统端到端验收。每个场景都有明确的前置条件、操作步骤和期望结果。

---

## 前置环境

| 条件 | 说明 |
|------|------|
| 服务状态 | `control-plane` 与 `web-ui-bff` 服务均已启动 |
| 数据库 | SQLite 数据库已完成迁移（`bun run db:migrate`） |
| 初始账号 | 至少存在一个 `platform_admin` 角色账号 |
| 浏览器 | 通过前端地址可正常访问登录页 |
| 自动化检查 | `bun run check:all` 通过 |

---

## 场景 1：管理员创建新用户（含首次强制改密）

**角色**：platform_admin

**步骤**：

1. 使用管理员账号登录系统
2. 进入「用户管理」页面（侧导航 → 用户管理）
3. 点击「新建用户」按钮
4. 填写：用户名 `testuser01`、显示名 `测试用户01`、密码 `Test1234!`、角色选 `developer`
5. 勾选「首次登录需改密」（mustChangePassword）
6. 提交

**期望结果**：

- 用户列表中出现 `testuser01`，状态为 `active`
- 角色显示 `developer`

**关联 API**：`POST /api/users`

---

## 场景 2：新用户首次登录强制改密

**角色**：场景 1 中创建的 testuser01

**步骤**：

1. 退出管理员账号
2. 使用 `testuser01` / `Test1234!` 登录
3. 弹出强制改密弹窗

**期望结果**：

- 弹窗无法关闭（无关闭按钮、点击蒙层无效、ESC 无效）
- 输入新密码（≥8 位）和确认密码，两次一致后点击确认
- 改密成功后弹窗消失，正常进入系统
- 后续登录不再弹出改密弹窗

**关联 API**：`POST /api/auth/login` → `PATCH /api/auth/me`

---

## 场景 3：用户自助更新资料

**角色**：任意已登录用户

**步骤**：

1. 进入「设置」页面（侧导航 → 设置）
2. 修改「显示名称」为新值，如 `新测试名称`
3. 可选修改「邮箱」
4. 点击「保存资料」

**期望结果**：

- 保存成功后显示名称在导航栏/个人信息处同步更新
- 刷新页面后修改保持生效
- 空白显示名称无法提交（前端拦截）

**关联 API**：`PATCH /api/auth/me`（body: `{ displayName, email }`）

---

## 场景 4：用户自助修改密码

**角色**：任意已登录用户

**步骤**：

1. 进入「设置」页面
2. 在密码区域填写「当前密码」、「新密码」（≥8 位）、「确认新密码」
3. 点击「更新密码」

**期望结果**：

- 新密码 < 8 位时前端拦截，不提交
- 新密码与确认不一致时前端拦截，不提交
- 当前密码错误时后端返回错误提示
- 修改成功后使用新密码可正常登录

**关联 API**：`PATCH /api/auth/me`（body: `{ currentPassword, newPassword }`）

---

## 场景 5：管理员禁用账户

**角色**：platform_admin

**步骤**：

1. 进入「用户管理」页面
2. 找到目标用户的操作列
3. 点击「禁用」并确认

**期望结果**：

- 用户状态变为 `disabled`
- 该用户立即无法登录（尝试登录返回禁用提示）
- 该用户已持有的 token 刷新时被拒绝
- 管理员无法禁用自己的账号（后端保护）

**关联 API**：`PUT /api/users/:userId/status`（body: `{ accountStatus: "disabled" }`）

---

## 场景 6：管理员恢复账户

**角色**：platform_admin

**步骤**：

1. 进入「用户管理」页面
2. 找到已禁用用户的操作列
3. 点击「启用」并确认

**期望结果**：

- 用户状态恢复为 `active`
- 该用户可重新登录

**关联 API**：`PUT /api/users/:userId/status`（body: `{ accountStatus: "active" }`）

---

## 场景 7：管理员变更用户角色

**角色**：platform_admin

**步骤**：

1. 进入「用户管理」页面
2. 找到目标用户，修改角色下拉（如 `developer` → `project_admin`）

**期望结果**：

- 角色变更成功，列表即时更新
- 审计日志中写入角色变更事件（包含 actor、目标用户、旧角色、新角色）
- `org_admin` 仅可管理非 `platform_admin` 用户

**关联 API**：`PUT /api/users/:userId/role`

---

## 场景 8：管理员编辑用户信息

**角色**：platform_admin 或 org_admin

**步骤**：

1. 进入「用户管理」页面
2. 点击目标用户行的「编辑」按钮
3. 修改显示名称/邮箱/密码（可选）
4. 确认提交

**期望结果**：

- 用户信息更新成功
- 如设置了新密码，用户需使用新密码登录

**关联 API**：`PATCH /api/users/:userId`

---

## 场景 9：非管理员访问权限检查

**角色**：developer / viewer

**步骤**：

1. 使用非管理员账号登录
2. 尝试访问「用户管理」页面

**期望结果**：

- 页面显示「无权访问用户管理」提示
- 不发起用户列表 API 请求
