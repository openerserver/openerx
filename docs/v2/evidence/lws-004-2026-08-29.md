## 1. 实际边界

```text
Tool Center 可信表单
  -> Main IPC（trusted sender）
  -> App Service command
  -> local_web_search_settings（owner_profile_id 隔离）
  -> 生成新的 FrozenLocalWebSearchConfiguration
  -> 只供后续 Generation 使用

Generation -> LocalWebSearchCoordinator
  -> 当前唯一选中的百度或 Bing Provider
  -> success / challenge / 429 / schema drift
  -> in-memory Provider health
  -> Tool result summary + Source -> Run / Renderer
```

Renderer 不使用 `localStorage` 保存搜索设置，模型工具 schema 也没有 Provider、locale、SafeSearch、
URL、Header 或 fallback 字段。UI 保存固定生成 `providerOrder=[selected]`、
`allowProviderFallback=false`、`cacheMode=turn`；因此模型不能选择搜索引擎，也不能把同一个 query 自动
扩散给多个 Provider。

## 2. 持久设置和 Generation 冻结

SQLite migration v16 新增 `local_web_search_settings`，只接受：

- `direct:baidu-json` 或 `direct:bing-html`；
- `zh-CN` 或 `en-US`；
- `off`、`moderate` 或 `strict` SafeSearch；
- profile owner 与更新时间。

Repository 测试证明设置重开后仍存在、不同 profile 不可见。App Service 测试先准备百度 Generation，
再保存 Bing/en-US/strict：旧配置仍保持百度和原 digest，新 Generation 得到 Bing 和新 digest。

## 3. Provider 状态机

- 首次 challenge/429：记录稳定错误，Provider 仍可用，连续失败数为 1；
- 连续第 2 次 challenge/429：Provider 进入 30 分钟 `backed_off`，readiness 变为 unavailable；
- 退避期间：不执行 Provider 网络请求，直接返回 `LOCAL_SEARCH_PROVIDER_UNAVAILABLE`；
- 窗口到期：自动恢复 available；成功后清零连续失败并记录 `lastSuccessAt`；
- `LOCAL_SEARCH_RESULT_SURFACE_UNRECOGNIZED`：立即进入 `schema_blocked`，应用重启或用户手动 reset
  前不再请求；
- “清缓存并重置退避”清除 Turn cache 和内存健康状态，但不重置每 Turn 调用预算。

这些运行状态不写入 SQLite；持久层只存用户选择，避免一次网络故障在下次启动后永久污染配置。

## 4. Renderer 和结果可见性

Tool Center 显示：

- Local Alpha feature flag 开/关；
- 当前 Provider、语言和 SafeSearch；
- 每个 Provider 的 available/backed-off/schema-blocked/unavailable；
- 退避截止时间和最近稳定错误码；
- 单 Provider、Turn cache、禁止自动 fallback、模型不可选择 Provider 的边界提示；
- 保存和手动 reset 操作。

工具成功摘要固定包含 Provider、`live` 或 `turn cache`、结果数、耗时和可选 `partial`。Turn cache 命中
时同时改写模型可见文本中的 execution mode 和 duration，不会把缓存结果描述为一次新的 live 请求。
失败继续在 Tool Activity 中显示稳定 `LOCAL_SEARCH_*` 错误码。

## 6. 真实受控 HTTPS 冒烟

同一命令分别执行百度和 Bing 真实 Provider，使用产品 User-Agent、受控 DNS/SNI/origin/path、512 KiB
上限，不启动 Browser：

- Bing HTML：通过，测试体 619 ms，Provider/result/source 边界全部满足；
- 百度 JSON：305 ms 后收到 challenge/3xx，稳定映射为 `LOCAL_SEARCH_PROVIDER_CHALLENGE`；未跟随
  重定向、未重试、未换 UA、未自动查询 Bing。

百度的这次失败不是代码门禁失败，也不能改写成成功证据；它是 LWS-006 必须继续量化 challenge 率的
真实 Provider 证据。默认 Provider 暂不因单次样本改动，用户已可在可信设置中显式选择 Bing。
