# 工作区目录重设计 · 2026-09-11

范围：本机 macOS arm64 openerx Desktop 的对话工作区入口。参考 [Codex 的项目组织方式](https://learn.chatgpt.com/docs/projects)：项目提供共享背景与目录，每个任务有明确的当前工作位置。本次使用现有本机授权和项目继承机制，不新增 Git worktree、Cloud 环境或磁盘迁移。

## 已实现的行为

- 对话标题下显示当前工作目录，点击可打开“工作区与附件”。
- 面板先显示项目来源，再显示一个“当前工作目录”和按需连接的“附加目录”。相同规范化路径只显示一个实际生效的授权；项目模板授权不再作为另一张对话目录卡片。
- 添加附加目录不会替换当前主目录。已连接的目录可设为工作目录，保留其访问权限、网络设置和有效期。用户明确设置的主目录不会被下一轮项目同步覆盖；移除本对话覆盖后可恢复项目目录。
- 重复选择同一路径复用授权；变更访问设置时，在同一事务中撤销旧的对话授权及其能力范围。按“主目录优先、对话授权优先”选择单条有效记录，不把不同记录的权限做并集，不删除历史授权记录。
- 访问和来源保留简短摘要，权限详情与操作折叠。只有点击“更换”或“添加”时才显示目录选择设置，有效期和 Shell 网络收在“更多权限设置”。
- 附件区域位于目录之后，导入操作明确说明不会改变工作目录；已有附件列表折叠。根目录下原有输出、相对路径及 HTML 资源关联不变。
- `workspace.list` 在对话空闲时先同步项目目录，使首次打开的目录与下一轮使用的目录一致；正在生成时不做项目目录同步。
