# PBASH-004A 本机实现证据（2026-08-28）

## 结论

状态为 `LOCAL COMPLETE / DIRECT WORKSPACE CHANGE EVIDENCE / ISOLATED MODE FAIL-CLOSED`。

本检查点完成基础直接写的变更可见性和恢复边界，并为高隔离请求建立不可降级的冻结合同。它不表示
CoW/worktree `WorkspaceChangeSet`、审阅后应用/丢弃或端到端 Remote 已完成；这些属于 PBASH-004B 和
PBASH-005。

## 已验证合同与执行路径

1. `brokered_bash_v1` execution context 新增模型不可见的 `workspaceWriteMode`：
   `none / direct_workspace / isolated_change_set`。只读 profile 只能是 `none`，写 profile 必须明确选择
   两种写模式之一。
2. Local/attended 默认直接写。`remote_unattended` 或 `requiresHighIsolation` 只生成
   `isolated_change_set`；当前 adapter 在 spawn 前返回
   `BROKERED_BASH_ISOLATED_CHANGE_SET_UNAVAILABLE`，没有 direct-write fallback。
3. macOS Runner 对全部可写 grant 在命令前后收集快照，跳过符号链接目标和任意层级 `.git`，结果不含
   宿主绝对路径。
4. 结果包含 pre/post revision、Git baseline/final status、dirty overlap conflict、创建/修改/删除/重命名
   manifest、受限文本 diff，以及固定的 `DIRECT_WORKSPACE_WRITE / NOT_AVAILABLE_FOR_DIRECT_WRITE`。
5. 文本捕获单文件最大 1 MB、diff 合计最大 5 MB、manifest 最大 10,000 项；二进制和超大文件仅提供
   类型、路径和大小。diff 继续使用现有 typed ToolResult content，Pi 和 UI 不需要解析自由文本。
6. hard-link 边界在执行前后都检查；Seatbelt 继续拒绝运行时新增 hard link/file clone 和任意层级
   `.git` 写入。

## 负向与边界用例

| 用例 | 结果 |
| --- | --- |
| 创建、修改、删除、rename | manifest 分类正确；创建/修改/删除生成 typed diff |
| 二进制文件 | `diffStatus=binary`，不返回内容 |
| 大于 1 MB 文件 | `diffStatus=too_large`，不返回内容 |
| 根和嵌套 `.git` | 不进入快照；真实 macOS 写入由 Seatbelt 拒绝 |
| 已 dirty tracked path 再被命令修改 | `conflictStatus=preexisting_dirty_overlap` |
| 新增 hard link/file clone | Seatbelt 拒绝；pre/post hard-link 边界仍 fail-closed |
| 无人值守/高隔离写入 | 冻结为 `isolated_change_set`；后端不可用时 spawn 前稳定拒绝 |
| 非 Git 工作区 / Git 状态不可取得 | 分别返回 `not_repository` / `git_status_unavailable`，不伪报 clean |

## 已知边界与下一步

- 直接写快照只能证明“执行窗口内工作区发生了哪些 delta”，不能可靠区分每个字节来自 Bash 还是同时
  操作文件的用户；因此返回 `workspace_delta_during_execution`，不提供伪原子归因。
- `preexisting_dirty_overlap` 能提示旧 dirty path 被再次修改，但直接写模式本身没有通用 Undo。需要强
  恢复语义时必须选 `isolated_change_set`。
- PBASH-004B 仍需实现 working-copy 执行、持久化 `WorkspaceChangeSet`、审阅、原子应用/丢弃和 Undo
  前镜像。PBASH-005 再把真实 Remote attended/unattended 来源接到本检查点的可信路由字段。
