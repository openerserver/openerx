## 1. 已实现边界

### 1.1 环境 policy

- `BrokeredBashEnvironmentPolicy` 支持 `none/core/all` 与 `include/exclude/set`；优先级为基础模式、
  include、exclude、set，最后执行不可绕过的 Secret 名称和值过滤。
- App Service 在 Generation 准备阶段冻结 include 对应的宿主值；policy ID 与 SHA-256 digest 进入
  `BrokeredBashExecutionContext` 和 operation digest，Runner 拒绝 ID、digest 或实际 policy 不一致。
- 私有 Pi Host IPC 版本递增到 v6；旧 Host 不能把缺少 policy digest 的上下文静默当作新请求执行。
- Runner 记录最终展开环境的 SHA-256 digest，但结果、日志和 Pi 上下文均不记录环境值。
- 当前只有 `read_only/workspace_write`，没有独立评审的 `danger_full_access`，所以 `all` 在 Runner
  fail-closed；Remote 只接受默认 core + deny，fake Runner 也不宣称支持自定义 policy。

### 1.2 Secret canary

本机真实 Runner 测试把以下 canary 写入宿主环境，再通过 `include` 尝试继承：

- SSH Agent：`SSH_AUTH_SOCK`；
- Git/npm/pip：`GIT_ASKPASS`、`NPM_TOKEN`、`PIP_INDEX_URL`；
- Cloud/SCM：AWS、GCP、Azure、GitHub；
- Pi/Codex、数据库、宿主 HTTP(S) proxy；
- 名称无敏感特征、值包含 `token=...` 的伪装变量。

Runner 输出只包含显式安全变量和 Runner 内部变量，所有 canary 值均不存在。HOME/TMP、Git/npm/pip
hardening、逻辑 Workspace 路径和短生命周期 egress proxy 是 Runner 在过滤后生成的可信值，不从宿主
继承。

### 1.3 受控 HTTP(S) egress

- 默认 `network-deny-v1` 不变；Local 只有在活动 WorkspaceGrant 的 `allowNetwork=true` 且可信控制面
  提供 allowlist 时才能选择 `network-controlled-egress-v1`，风险仍按 L4 处理。
- Seatbelt profile 继续 `(deny network*)`，仅例外允许 Runner 随调用创建的
  `localhost:<ephemeral-port>` TCP proxy；Shell 和所有后代不能直连 DNS、回环或公网。
- Proxy 只支持 HTTP 请求与 HTTPS CONNECT 的 80/443，删除代理身份/转发头，不接受 URL 凭证；每次
  请求（包括客户端跟随重定向后的新请求）重新执行域名 allowlist 和 DNS 校验。
- HTTPS CONNECT 只允许 443，并在不解密 TLS 的前提下解析 ClientHello；无 SNI、非 TLS 或 SNI 与
  CONNECT authority 不一致时断开，避免利用共享 CDN IP 隧道到另一个虚拟主机。
- DNS 全答案必须都是公共、family 匹配的地址；任一答案属于 loopback、RFC1918、link-local、CGNAT、
  multicast/reserved、IPv4-mapped 私网、IPv6 ULA/link-local 或 metadata 范围即整次拒绝。连接直接使用
  已验证 IP，避免校验后再次解析。
- HTTPS 保持端到端 TLS，代理不解密内容；下载结果仍在同一文件、进程和变更证据边界内执行。

## 2. 本机真实证明

`MacOSSandboxExecEngine` 合同测试实际执行：

1. allowlist 为 `example.com` 时，`curl https://example.com/` 经受控代理成功；
2. 同一 Shell 中 `curl --noproxy '*'` 直连失败；
3. 默认 policy 下访问随机本机 HTTP 端口失败；
4. Secret canary 通过 `/usr/bin/env` 验证不在 Runner 环境；
5. `all` 在现有 profile 下返回 `BROKERED_BASH_ENVIRONMENT_ALL_DENIED`。

## 3. 负向矩阵

| 边界 | 结果 |
| --- | --- |
| 默认 DNS/IPv4/IPv6/回环直连 | Seatbelt deny，既有 PBASH-002 测试继续通过 |
| allowlist 外域名、伪后缀、wildcard 父域 | `BROKERED_BASH_EGRESS_DOMAIN_DENIED` |
| 22 等非 HTTP(S) 端口、非 443 CONNECT | `BROKERED_BASH_EGRESS_PORT_DENIED` |
| URL/CONNECT 携带用户名密码 | `BROKERED_BASH_EGRESS_CREDENTIALS_DENIED` |
| CONNECT 后非 TLS、无 SNI、错 SNI | 握手前断开，不建立上游连接 |
| localhost、私网、metadata、CGNAT、IPv6 ULA/link-local | `BROKERED_BASH_EGRESS_ADDRESS_DENIED` |
| 公网 + 私网混合 DNS、family 伪造 | 整组答案拒绝，不选择“看起来安全”的单个地址 |
| 重定向到非 allowlist 域名 | 客户端下一跳重新经过 proxy 并拒绝 |
| Remote 请求自定义环境或 egress | Bash 工具不投影；合同仍要求默认 core + deny |
| `all` 或 fake Runner 自定义 policy | 不可用，拒绝而非退回宿主环境/裸 Bash |

## 5. 未外推的结论

- 这是当前 macOS 主机的本地实现证据，不是 Developer ID 签名包、公证、生产 Remote 或跨 OS 证据。
- controlled egress V1 只支持 HTTP(S) 80/443，不支持 UDP、任意 TCP、私网服务或凭证注入。
- `/usr/bin/sandbox-exec` 已 deprecated；替代后端、签名安装包和 macOS 支持矩阵仍属于 PBASH-008。
- Linux/WSL2/Windows 没有等价 Runner 时继续 unavailable/fail-closed。
