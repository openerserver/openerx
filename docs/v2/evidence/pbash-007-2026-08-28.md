## 1. 固定 A/B 边界

本检查点使用同一临时工作区、同一命令文本、同一 15 秒 timeout 和默认断网，对比：

- A：现有 `ShellToolAdapter`，通过 argv 启动 `/bin/bash --noprofile --norc -c`；
- B：`MacOSSandboxExecEngine`，使用 `read_only + core + network deny` 执行 Brokered `bash`。

固定任务覆盖仓库探索、组合搜索、构建、测试、lint、失败诊断、补丁前验证、长输出和停止。每个
Brokered 结果都必须证明 filesystem boundary、environment sanitized、network denied，且 controlled
egress 未开启。本节的确定性 Runner 测试没有调用模型；真实模型指标由第 2.1 节的独立配对评测
补充，二者不能互相替代。

固定 `deepseek-v4-flash`、thinking off、同一快照与默认断网，9 类任务各做 3 次配对。严格完成率从
legacy 22/27（81.5%）提升到 Brokered 26/27（96.3%）；总 Token 从 61,473 降到 53,298（-13.3%），

失败是成功测试后的最后一行格式未遵循，功能工具结果仍为 27/27。

Pi 会把私有 Session cwd 追加进系统提示，本检查点因此在 Platform Provider 请求前定点脱敏该目录，
并在 `bash` 工具合同中声明命令从活动授权根启动。完整复跑中 Brokered 的活动工作区与 Pi 私有目录
绝对路径暴露均为 0。详见 [真实模型 A/B 证据](pbash-007-model-ab-2026-08-28.md) 和
[机器可读原始记录](pbash-007-model-ab-2026-08-28.json)。

## 3. 渐进启用与回滚

- `OPENERX_BROKERED_BASH_V1` 继续默认关闭；`undefined/0/false` 为关闭，`1/true` 为开启。
- flag 关闭时只投影 `openerx_shell`/`openerx_shell_process`；开启且 Runner probe 通过时只投影 `bash`。
- 开启但 Runner probe 失败时两类 Shell 都不投影，不静默回退到旧 Shell 或 Pi 内置 Bash。
- 关闭 flag 不迁移、不删除、不重放历史 ToolCall；回滚只改变下一次 Generation 的工具投影。
- 工具中心现在展示 Local Alpha、Runner、sandbox policy、core Secret-filtered 环境、默认断网和有效
  workspace 数；关闭时展示 `openerx_shell` 回滚路径和“不会同时暴露”提示。

App Service 与 Desktop 定向结果：`tool-app-service.test.ts` 16 个测试通过，`chat-ui.test.tsx` 30 个
测试通过；Contracts、Tool SDK、App Service、Desktop typecheck 通过。
