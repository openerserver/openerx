## Implemented request path

```text
React Renderer
  -> frozen typed Preload Bridge
  -> fixed Main IPC handler + sender check
  -> supervised App Service utility process
  -> transactional SQLite ChatRepository
  -> private Runtime port
  -> Runtime Host utility process
  -> fake-runtime/v1
  -> ordered product event replay to Renderer
```

Runtime handles never become history. App Service resolves Conversation/Message snapshots before an
adapter invocation and persists each accepted product event before broadcasting it.

## Security and recovery proof

- Main rejects a sender frame that is not its WebContents main frame.
- App Service startup rejects unknown versions, malformed nonces, nonce mismatch and handshake replay.
- CSP exposes no localhost App Service route; Main creates both private MessagePorts.
- Renderer has no Node globals and cannot access filesystem, process or raw `ipcRenderer`.
- Database startup runs ordered checksum validation and `PRAGMA quick_check`; corrupt or newer databases
  fail closed instead of being replaced.
- M1 schema inspection finds no reusable credential, password, secret or token table.
- Command idempotency, runtime sequence and terminal-state checks prevent duplicate writes and
  post-stop deltas.

## Platform boundary and residual risk

- macOS arm64 is the current native host and has both packaged startup and Playwright interaction
  evidence.
- macOS x64 and Windows x64 were cross-packaged from current M1 source and passed Fuse inspection.
  Their native Playwright E2E jobs are committed in `.github/workflows/v2-ci.yml`; hosted native results
  cannot exist before this local commit is pushed. They remain required before release distribution.
- Packages are unsigned development artifacts. Signing, notarization, installation, update and rollback
  remain M8 gates.
- `node:sqlite` is experimental. M1 contains it behind `packages/storage`, checks integrity and fails
  closed, but automatic backup restore is not implemented.
- `fake-runtime/v1` is deterministic acceptance infrastructure, not model intelligence or a
  production alternative harness. The real Pi Harness Host, files and tools remain M4/M5 work.
