## Implemented runtime boundary

`apps/mobile` is a React Native + Expo control plane with fixed Hosts, Tasks, Inbox and Settings areas.
It keeps its controller private key and monotonic sequence in SecureStore, signs and encrypts product
commands, decrypts cursor events, and can require local biometric verification before higher-risk
decisions. It does not contain Pi, tool adapters, pricing logic or a desktop credential.

Remote Control Gateway stores Presence, pairing metadata, opaque command/event ciphertext, TTL,
delivery receipts, cursors and PushSubscription token references in SQLite. It can reject invalid
account/device/pairing metadata but cannot decrypt business payloads. The desktop Connector creates an
outbound transport, verifies/decrypts on the host and reaches App Service only through a private
MessagePort. The local Alpha transport is HTTPS polling; there is no desktop Remote listener.

App Service owns the final durable application record. Duplicate delivery with the same command and
payload returns the committed result; a changed payload is rejected. Remote Start, Steer, Queue and Stop
call the existing Pi path, while approvals re-enter the existing Capability Broker. No Remote-specific
agent loop, runtime queue, SessionManager, pricing estimate or Billing write path was added.

## End-to-end proof

The Electron fixture starts the real desktop process group and Platform Alpha services, then acts as an
authenticated encrypted iOS controller. It logs in the desktop and phone devices, funds server Billing,
enables Remote, pairs by proof, observes Presence, submits a signed encrypted task, receives a real model
response through Pi and decrypts the product event cursor. Redelivering the exact command replays the
application result and leaves one server Charge. The flow then revokes the pairing, disables Remote and
confirms the desktop host private key is not present as plaintext.

## Evidence boundary and remaining release gates

This checkpoint does not claim the Remote Alpha release exit condition. The following evidence remains:

- iOS and Android real-device execution, Keychain/Keystore behavior, biometric prompts, QR camera and
  notification deep links;
- Windows x64 and macOS x64/arm64 signed host packages across the required phone/host matrix;
- production HTTPS/WSS deployment and APNs/FCM provider delivery; local tests register an opaque push
  token reference but do not call a production push provider;
- mobile photo/file object upload through Account Sync/Object Store and opening the result on desktop;
- real-device Diff, test, terminal, screenshot and Artifact review resources, including large/paged data;
- host sleep/app exit, real network switching, lost phone and multi-controller fault exercises.

The local Node runtime is 24.2.0 while React Native 0.86.2 reports support from Node 24.3.0. Both iOS and
Android Hermes exports passed, but the release builder must be upgraded before native release evidence.

`npm run audit:prod:v2` passes the configured high-severity gate, but npm reports 10 moderate findings
from Expo's transitive `xcode@3.0.1 -> uuid@7.0.3` build dependency. npm's suggested forced fix would
downgrade Expo across a breaking boundary, so this checkpoint does not apply it. Upgrade or upstream
resolution of that build chain remains a release dependency; the finding must be re-audited with the
native release toolchain.
