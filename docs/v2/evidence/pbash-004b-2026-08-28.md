# PBASH-004B 本机实现证据（2026-08-28）

## 结论

状态为 `LOCAL COMPLETE / APFS COW WORKING COPY / PERSISTED WORKSPACE CHANGE SET`。

本检查点完成 PBASH-004 的高隔离写入闭环：命令不直接写宿主工作区，变更先持久化为可发现、可审阅的
`WorkspaceChangeSet`，再经冲突检查和单次审批应用、丢弃或撤销。它不代表 PBASH-005 的真实 Remote
投递、断线重放或外部系统对账已经完成。

## 执行与持久化

1. `workspaceWriteMode=isolated_change_set` 时，macOS Runner 以 `/bin/cp -cRp` 从命令开始时的当前
   Workspace 建立 APFS copy-on-write 副本。已有未提交修改包含在基线中；原可写根不作为命令的可写
   sandbox root。
2. 命令、子进程、HOME、TMP 和 cache 全部位于 Runner 边界；销毁进程组后才收集 change set，随后删除
   working copy。
3. SQLite migration v14 新增 `workspace_change_sets`，持久化 active grant、Run、ToolCall、pre/post
   revision、manifest、diff、受控 before/after 材料和状态。
4. 模型结果只包含公开 manifest/diff 与 change-set ID/status；内部 materialization 在 Broker 写入数据库
   后从 ToolResult data 删除。
5. `openerx_workspace_changes` 同时列出单文件变更与 change set，重启后仍可重新发现。

## 审阅、应用与恢复状态机

```text
pending_review -> reviewed -> applying -> applied -> reverted
       |             |                      |
       +----------> discarded              +-- hash conflict: reject

blocked -> discarded
applying -- process crash --> outcome_unknown -- recoverable states --> reverted
```

- review 是显式状态门；未 review 不能 apply。
- apply/undo 是 L3 per-call 审批，不复用持久 Scope 静默执行。
- apply 写入前验证全部 grant 为 read-write、所有相对路径不含 `.git`、所有 before hash 匹配且 rename
  目标不存在。任一冲突发生在第一笔写入前。
- 支持文本文件的创建、修改、删除和 rename。多文件写入中途失败会按逆序恢复全部 preimage。
- Undo 只有在所有 after hash 仍匹配时执行，避免覆盖 apply 后用户继续编辑的内容。
- App Service 崩溃时 `applying` 转为 `outcome_unknown`；只有每项处于记录的 before/after 状态才允许
  恢复 Undo，第三种内容 fail-closed。

## 负向与资源门禁

| 用例 | 结果 |
| --- | --- |
| 隔离命令创建/修改文件 | change set 持久化；宿主 canary 不变 |
| 未 review 直接 apply | `WORKSPACE_CHANGE_SET_NOT_APPLICABLE` |
| 用户在基线后修改目标 | `WORKSPACE_CHANGE_SET_CONFLICT`，零文件被覆盖 |
| 二进制、超 1 MB、目录、symlink、不可表达项 | set 状态 `blocked`，只能审阅/丢弃 |
| `.git` | Runner 写入拒绝；应用层再次拒绝受保护路径 |
| `node_modules`、Python/Gradle/Next/Yarn cache | 留在 overlay，记录 `excludedPathCount`，不进入 change set |
| materialization 总量 | 单文件 1 MB、全部快照文本 20 MB；超限转 blocked |
| apply 中断 | 状态 `outcome_unknown`，按已知 before/after 状态恢复或冲突拒绝 |
| apply 后用户再编辑 | Undo hash 校验失败，不覆盖新内容 |

## 本机复现

```bash
npm run test --workspace @openerx/tool-sdk
npm run test --workspace @openerx/storage
npm run test --workspace @openerx/contracts
npm run test --workspace @openerx/pi-host
npm run test --workspace @openerx/app-service
npm run typecheck --workspaces --if-present
npm run lint:v2
npm run check:v2
git diff --check
```

定向证据覆盖：真实 macOS CoW working copy、AppService→Broker→Runner change-set 持久化、typed review
diff、创建/修改/删除/rename apply、Undo、blocked/discard、旧基线冲突、per-call 审批策略、20 MB 内存
上限和崩溃恢复。最终 `check:v2` 退出码为 0：83 个测试文件、432 项测试通过；iOS/Android export、
Desktop macOS arm64 重新打包、fuses 与 release artifact 校验通过。native signature 按本地模式明确为
`LOCAL UNSIGNED`，不冒充签名发布证据。
