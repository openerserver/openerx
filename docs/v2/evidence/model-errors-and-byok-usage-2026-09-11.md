# openerx 模型错误分类与 BYOK 用量记录

验证日期：2026-09-11，Asia/Shanghai。结论：LOCAL VERIFIED。

已补齐模型错误的具体原因和自带 API Key 的本地用量记录。新版本中的模型调用可以关联到消息、执行 Run 或后台记忆任务；用户在消息的“运行详情”和执行轮次用量中查看记录。

## 已实现

错误通过共享分类器归类为鉴权、权限、额度、限流、超时、网络、供应商服务、上下文上限、输出上限、响应格式、请求参数、模型不存在、配置、能力、内容拒绝、取消及原因未知，并保留可确认的 HTTP 状态与是否适合重试。消息展示相应的中文处理提示，运行失败事件写入安全错误码。平台登录失效保留独立身份错误码。旧的 `PI_PROVIDER_FAILURE` 显示原因未确认。

BYOK 在 Pi 实际消费供应商流时读取原始 usage，经过独立的 `pi.model-usage` 事件传给 App Service，存入当前用户配置下的 SQLite。覆盖对话、工具循环、Pi 内部模型调用、SDK 重试、自动记忆提取与记忆聚类。每次实际 HTTP 请求有独立记录；失败及取消时保留已经收到的用量。同一事件重放不会重复入账。后台调用有独立 operation 与 operationId。

记录包含模型选择、实际返回模型、开始及记录时间、调用状态、错误分类，以及输入、缓存、输出、推理和总 Token。输入为非缓存部分，另外保存原始 promptTokens。推理 Token 是输出的组成部分，不再次加到总数。总 Token 仅使用供应商返回的值；未返回的字段保存为 null，并记录缺失原因，界面显示未知。供应商重复发送累计 usage 时不累加快照。

本地 BYOK 记录明确标记 `source=byok`、`accountId=null`，平台计费记录的原有 schema 仍拒绝 BYOK 数据。BYOK 查询无需平台登录；指定历史消息时按消息的模型来源查询。新增记录与诊断事件不保存 API Key、提示词或原始供应商错误文本。

## 存储与兼容

- SQLite migration 33 新建 `byok_usage_records`，按用户配置隔离；消息及对话关联经过校验。关闭并重新打开应用后可继续查询。
- 执行 Run 完成、失败、取消时合并已有记录，避免结束事件覆盖之前的消耗。
- 对话软删除后的迟到用量可被安全接收，已删除对话的记录不出现在用量查询中；清理本地缓存包含新表。
- Pi Host 契约版本升级为 11，Desktop、App Service 与 Pi Host 必须使用同一构建。
- 当前只记录新版本处理的新调用；历史空记录不推算补填。设置页的“测试连接”已接入错误分类，其探测请求不进入本次对话/后台任务用量表。
- 按消息查询保留历史来源；未指定消息的总览按当前运行模式返回相应用量。混合来源的会话不提供合并的跨来源账单。
- 本地记录用于诊断供应商报告的消耗，金额及最终计费以供应商账单为准。进程被强制结束且尚未回传的调用不保证有完整记录。
