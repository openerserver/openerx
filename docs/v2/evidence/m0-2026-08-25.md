## Packaged application smoke

The packaged macOS arm64 application was started from
`apps/desktop/out/UWA-darwin-arm64/UWA.app`. Accessibility inspection and a local DevTools
session against that process confirmed:

- title `UWA`, heading `今天想完成什么？`, route
  `openerx://renderer/index.html#/chat/new`;
- suggestion `分析表格中的关键变化` fills the composer and enables the send button;
- submit displays `交互已记录；消息运行闭环将在 M1 Chat Alpha 接入。`;
- bridge result is `{ platform: "darwin", arch: "arm64", appVersion: "0.0.0" }`;
- Renderer reports `typeof process === "undefined"`;
- `window.openerx` exposes only `getEnvironment`.

The custom `openerx://` production protocol replaces privileged `file://` loading. Package
verification recorded the following on all three targets:

- disabled: RunAsNode, NODE_OPTIONS, CLI inspect, browser-specific snapshot and file-protocol extra
  privileges;
- enabled: cookie encryption, embedded ASAR integrity, ASAR-only loading and WebAssembly trap
  handlers;
- `strictlyRequireAllFuses: true` fails packaging if a future Electron adds an unknown fuse.

## CI and release boundary

`.github/workflows/v2-ci.yml` runs portable quality gates and packages Windows x64, macOS arm64 and
macOS x64 with Fuse verification. The workflow has not yet run on GitHub in this local checkpoint;
the local cross-target package evidence proves configuration viability, while the first push/PR will
provide hosted-run evidence.

All M0 artifacts are unsigned development packages. Windows signing, macOS Developer ID signing and
notarization, publishing, auto-update and rollback remain later release gates and must not be inferred
from this result.

## Known contained risks

- Electron Forge's Vite plugin is experimental. Exact Forge/Vite versions are pinned; upgrades must
  pass the warning-free three-target matrix.
- `node:sqlite` is a release-candidate Node API. ADR-V2-005 isolates it behind `packages/storage`; M1
  must add migration, corruption-recovery and encrypted-field tests before Chat Alpha.
- The full development-dependency audit reports 30 findings (3 low, 26 high, 1 critical) inherited
  from the current stable Electron Forge packaging chain, primarily archive/image tooling. They are
  not shipped runtime dependencies and the production audit is clean, but they remain an open
  supply-chain risk. CI installs only the integrity-pinned lockfile, packages trusted repository
  inputs and runs the production audit; Forge/transitive updates must be tested as fixes become
  available.
- Windows and macOS x64 packages were cross-packaged and structurally verified, not launched on those
  operating systems. Native install/start smoke is an M1 and release gate.
