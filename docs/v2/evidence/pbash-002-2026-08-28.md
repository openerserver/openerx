## 1. 本切片交付

1. 新增稳定 `PlatformSandboxEngine` 合同，覆盖 capability、根映射、执行 profile、环境/网络 policy、
   资源上限、执行结果、backend proof 和进程树销毁状态。
2. 新增显式 `fake | macos` runner mode。`OPENERX_BROKERED_BASH_V1` 仍默认关闭；真实模式还必须显式
   选择 `OPENERX_BROKERED_BASH_RUNNER=macos`。未知配置、非 macOS、缺失组件或 capability 自检失败
   均 fail-closed。
3. 新增 `MacOSSandboxExecEngine`：使用外部 `/usr/bin/sandbox-exec` 进程承载
   `/bin/bash --noprofile --norc`，应用版本化 `macos-seatbelt-v1`，不启用 Pi builtin Bash。
4. 新增真实 `BrokeredBashAdapter`：重新解析当前 WorkspaceGrant，精确比较 Generation 冻结上下文，
   只把受信绝对根传给平台引擎，并把 backend/policy/OS/销毁证明投影为标准 ToolResult。
5. App Service 只有在 capability 完整、活动根明确且 policy 匹配时才投影产品 `bash`；真实模式不可用
   时不会恢复 Pi Bash，也不会与 legacy `openerx_shell` 同时暴露。
6. Pi 模型参数仍只有 `command + timeout`。真实模式描述明确工作区 profile、默认断网和附加根逻辑变量，
   不暴露 grant ID 或宿主路径。
7. PBASH-002 只返回有界最终输出；实时 stdout/stderr chunk、跨 chunk 脱敏和完整日志 Artifact 明确留给
   PBASH-003。

## 2. macOS 强制边界

### 2.1 文件与根

- 所有 grant 根在执行前 `realpath`；不存在、非目录、文件系统根、宿主 HOME、`.git` 内部根、重复或
  嵌套根均拒绝。
- `read_only` 只写 Runner 私有 HOME/TMP/cache；`workspace_write` 只写 read-write grant。
- 任意层级 `.git` 均由 Seatbelt regex 拒绝写入；只读额外根不能被写。
- 符号链接按最终目标受到 Seatbelt 约束。
- 每次执行前最多扫描 250,000 个授权根条目并按 device/inode/nlink 对账。只要 hard link 还有授权根
  集合外别名，或同一 inode 同时存在 writable/read-only 别名，就返回
  `BROKERED_BASH_HARDLINK_BOUNDARY_UNSAFE`，不启动 Shell。
- profile 额外 `(deny file-link file-clone)`，阻止命令在运行期间从只读根或外部路径建立新别名。

hard-link canary 首次加入时确实发现了 Seatbelt 路径规则的缺口：根内预置硬链接可以改写根外同一
inode，原始负向测试得到 exit 0。最终实现加入 inode 预检和运行时 link/clone deny 后，同一 canary 的
读、写与跨只读根创建均 fail-closed；根外文件保持原值。该失败不是从证据中删除的“过程噪音”，而是
本切片新增防线的直接依据。

### 2.2 最小运行时与环境

- 环境从空集合构造，使用 Runner 私有 `HOME/TMPDIR/XDG_CONFIG_HOME/XDG_CACHE_HOME`。
- 不继承 `SSH_AUTH_SOCK`、`CODEX_*`、`PI_*`、`OPENAI_*`、云 Token、Git/npm/pip 用户配置或宿主 HOME。
- `GIT_CONFIG_NOSYSTEM=1`、Git/npm/pip 配置固定为 `/dev/null` 或 Runner cache；
  `OPENSSL_CONF=/dev/null`，使 Homebrew Node 无需读取宿主 OpenSSL 配置。
- 系统只读根由宽 `/usr`、`/opt/homebrew`、`/usr/local`、`/private/etc` 收紧为二进制、库、
  Cellar/opt/share、Xcode/Java、SSL 与动态加载器所需子目录。当前主机已验证
  `/opt/homebrew/etc/smartd.conf` 和 `/private/etc/hosts` 不可读。
- 附加授权根只通过 Runner 临时目录下的 `$OPENERX_WORKSPACE_1`、`$OPENERX_WORKSPACE_2` 等逻辑路径
  暴露；最终输出把真实工作区、Runner 临时目录和宿主 HOME 替换为占位符。

### 2.3 网络、进程与资源

- profile 为 `(deny default)`，显式拒绝 `network*`，无 `mach-lookup` broad allow。
- 进程权限仅允许 fork/exec，以及 self/children 的 signal/process-info；受控外部进程 canary 的环境
  不可读取，且不能被沙盒命令发送信号。
- 每个 ToolCall 使用独立进程组；自然退出、timeout、Abort、`stopAll`/App Service close 均先 TERM、
  后 KILL，并返回 `clean | terminated | killed | uncertain`。`uncertain` 作为失败处理。
- 应用 CPU、当前用户基线上的进程数、打开文件数、单文件大小和 stdout/stderr/合并输出上限；模型可见
  最终结果再限制为 50 KiB。

## 4. 关键负向与正向证明

| 门禁 | 最终结果 |
| --- | --- |
| Linux、缺失 `sandbox-exec`、缺失 Bash、伪 backend 自检 | capability unavailable，不投影真实 `bash` |
| 授权读与最小 Bash/Node 子进程 | 成功 |
| read-only 写、工作区外读写、符号链接逃逸 | 拒绝，canary 不变 |
| workspace_write 普通文件 | 成功 |
| 顶层/嵌套 `.git`、只读额外根 | 拒绝，原值不变 |
| 外部 hard link 读写、writable/read-only 跨根 hard link | 预检或运行时拒绝，根外/只读文件不变 |
| 全部别名均位于同一 writable 授权集合的 hard link | 允许，两个授权别名一致更新 |
| `/`, HOME, `.git` 内根、缺失根、重复/嵌套根 | 启动前拒绝 |
| 宿主环境、包管理器配置、Homebrew/private-etc 配置 | 不可继承或不可读 |
| 回环 HTTP | 拒绝；本地测试 Server 未收到内容 |
| 外部进程环境与 signal | 不可读、不可发送 |
| 自然退出残余后代、timeout、Abort、stopAll | 进程组回收；PID 不再存在 |
| 超限输出 | Runner 截断；Broker 模型上下文保持 50 KiB |
| App Service → Broker → macOS backend | 真实执行，proof 为 `macos_sandbox_exec` / `macos-seatbelt-v1` |
| 当前仓库 opt-in `workspace_write` + Node smoke | 通过 hard-link 预检并输出 `pbash-repo-smoke` |

## 6. 启用、回滚与未完成

- 默认仍不启用新 Bash。真实本机 opt-in 同时需要
  `OPENERX_BROKERED_BASH_V1=1` 与 `OPENERX_BROKERED_BASH_RUNNER=macos`。
- 关闭 feature flag 恢复现有 legacy `openerx_shell`；一个 Generation 内不会同时暴露两套 Shell，也
  不会恢复 Pi builtin `bash/read/write/edit`。
- fake mode 仍作为确定性合同测试路径，不能冒充真实执行结果。
- 尚无有序实时 progress、跨 chunk 脱敏、完整日志 Artifact、changed-path manifest、通用 Undo、PTY、
  长期后台 Session、受控 egress、SecretRef、内存/总临时磁盘配额或无人值守 Remote working copy。
- hard-link 预检超过 250,000 条目或无法完整扫描时 fail-closed；其性能与更高隔离 working copy/CoW
  路线仍需 PBASH-004/PBASH-007 评估。
- 没有签名安装包内的 Runner 证据，没有 Apple 公证/Gatekeeper、未来 macOS 版本、Linux 或 Windows
  后端证据。`LOCAL UNSIGNED` 不是签名失败，也不是发布批准。
