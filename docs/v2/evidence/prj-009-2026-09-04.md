## 1. 已实现

- 新增严格 `Project` 与 `ProjectDirectory` 同步 payload：只允许项目元数据、说明、置顶/归档、逻辑目录显示名、主/附加角色、期望访问和 revision；逻辑目录删除只能使用空 payload 墓碑。
- `ProjectRepository` 在创建、更新、归档/恢复、添加/移除目录、切换主目录和移动对话时写入现有事务 outbox；重复 `operationId` 不产生重复同步写入。
- 主目录切换按“旧主目录降为附加 → 新主目录升为主目录 → 项目 revision”顺序入队，确保另一副本不会撞到单主目录唯一约束。
- `ChatRepository` 拉取端可恢复项目、逻辑目录和 Conversation `projectId`；另一设备不创建 `ProjectDirectoryBinding` 或 `WorkspaceGrant`，因此目录显示 `reconnect_required`。
- 逻辑目录墓碑会撤销接收设备上该目录的本机源 Grant、对话派生 Grant 和 Capability Scope；清理本机缓存后可从云端变更历史重建相同项目/对话状态。
- Account Sync 服务对项目对象增加 payload 级严格解析、账户/对象 ID 一致性检查，并递归拒绝路径、目录句柄、WorkspaceGrant 和 ProjectDirectoryBinding 权限字段。
- App Service 对已登录项目写入触发同一 `SyncCoordinator`；离线时本地事务和 outbox 保持有效。同步、冲突解决、缓存清理和云端删除后，Renderer 会刷新项目、对话和 Workspace 查询。
- 沿用现有 revision 冲突：项目两端版本均保留为可见冲突；Conversation 归属冲突继续由用户选择本地或云端最终值。

## 3. 安全结论

- 源设备 outbox 的序列化 canary 不包含真实 `rootPath`、源/派生 WorkspaceGrant ID 或 ProjectDirectoryBinding ID。
- 第二副本恢复逻辑目录后没有可执行授权，必须由用户在该设备通过系统选择器重新连接。
- 同步删除逻辑目录时，本机连接和对话派生授权 fail closed；项目对象本身仍不能成为权限主体。
- 服务端既执行递归权限字段拒绝，也对两种项目 payload 做严格对象 Schema 校验；伪造 owner/object ID 会被拒绝。
