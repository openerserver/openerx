## 1. 实现结果

新增 `npm run probe:lws:v2`，固定执行：

```text
direct:baidu-json ─┐
                   ├─ navigational / reference / current = 3 次请求
direct:bing-html ──┘
```

每个 Provider/Query 组合只请求一次；执行顺序固定，无重试、无自动 fallback、无 Browser、无结果页
请求。探测器需要显式的稳定产品 User-Agent，产物只保存 UA/query 的 SHA-256 摘要和聚合质量指标，
不保存原始查询、Source URL、SERP HTML/JSON、Cookie 或代理详情。

日期化产物：

- `docs/v2/evidence/lws-probes/2026-08-29.json`：机器可读的 6 次真实尝试；
- `docs/v2/evidence/lws-probes/2026-08-29.md`：当日人工摘要；
- `tests/v2/golden/lws-006-gate-status.json`：由全部日期报告重新计算的门禁，不手工填成功率。

探测日期必须等于当时 Asia/Shanghai 的自然日，CLI 拒绝历史回填；报告文件名也必须与内部日期一致。
重复日期会被汇总器拒绝，缺少任何固定 Provider/Query 组合也会失败，因此重复运行同一天或跳过失败
请求不能扩大样本。CLI 不提供覆盖参数；当天已有 JSON 或 Markdown 时会在联网前拒绝再次执行。

## 2. Stop 与资源释放

`NodeControlledSearchHttpClient` 现在同时跟踪 `ClientRequest` 和 `IncomingMessage`。Stop/Abort 先冻结
稳定结果为 `LOCAL_SEARCH_CANCELLED`，再销毁 response reader 和 request/socket；timeout 同样先冻结
`LOCAL_SEARCH_TIMEOUT` 再销毁资源，避免同步 socket error 把错误码竞态改写成 Provider unavailable。

确定性测试在响应已开始但未结束时触发 Stop，并证明：

- Promise 只以 `LOCAL_SEARCH_CANCELLED` 结束；
- request `destroy()` 恰好调用一次；
- response 已进入 destroyed；
- Stop 后推送的迟到正文返回 false，不能形成搜索结果提交。

## 3. 性能与历史门禁合同

Parser 性能测试分别对 100 条百度 JSON fixture 和 Bing HTML fixture 预热后执行 100 次，两个 P95
都必须小于 50 ms。网络历史门禁冻结为：

- 至少 7 个不同的 Asia/Shanghai 日期；
- 每个 Provider 每日 3 个固定查询，即每 Provider 至少 21 次计划请求；
- 成功率 `>= 95%`；
- 所有尝试总耗时的 P95 `< 3000 ms`；
- 缺失请求计入分母，不能通过漏报提高成功率；
- 前五相关性、重复率和 Source URL 合法率只记录为质量信号，当前不替代人工可打开性验证。

未满 7 日时状态只能是 `insufficient_history`。达到 7 日后，任一 Provider 未同时满足成功率和 P95
则为 `local_alpha_fail`；两者都满足才是 `local_alpha_pass`。即使 Local Alpha 通过，Release 仍固定
需要 Provider 条款、Source 可打开性/人工质量、macOS arm64+x64、Windows x64、签名安装升级回滚和
签名包完整 E2E，探测器不会把这些外部证据自动写成完成。
