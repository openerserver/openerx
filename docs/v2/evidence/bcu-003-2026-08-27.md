## Implemented runtime path

- `ElectronToolCapabilityHost` routes `operation: "browser_computer_use"` to
  `SystemDefaultBrowserAdapter`; Pi projects the strict `browser_computer_use_v2` tool by default.
- `OPENERX_BROWSER_COMPUTER_USE_V2=0` or `false` restores the frozen `legacy_dom_v1` path for new calls.
- macOS resolves the current HTTP(S) handler through `NSWorkspace`, supports Safari, Chrome, Chromium,
  Edge and Brave bundle families, and fails closed for an unsupported default browser.
- A dedicated top-level browser window is created and bound by bundle ID, PID, exact `CGWindowID` and
  bounds. Existing browser windows are not reused. The native helper raises, conditionally isolates,
  observes, acts on and closes only that bound window.
- Navigation does not publish its baseline Observation until window identity, URL, native bounds and
  `AXWebArea` bounds remain stable across eight consecutive samples. Targetless native actions use URL,
  surface and semantic page-revision validation, so caret-pixel blinking cannot invalidate a safe key while
  real focus/semantic changes still do.
- A compiled Swift Accessibility helper reads the visible `AXWebArea`, emits filtered semantic elements,
  redacts sensitive values and re-finds a unique action target by role, accessible name and absolute bounds.
- Electron `desktopCapturer` selects the exact native window, crops to the web area and pixel-masks every
  sensitive semantic rectangle before returning a typed PNG. It has no whole-screen fallback.
- Semantic element actions are primary. Native AX hit-testing is a constrained fallback for an observed
  point. Selectors, full DOM/HTML, page JavaScript, remote debugging and browser profile APIs are absent
  from the V2 tool contract and active driver.
- Named keys mutate only the focused, non-sensitive AX editable element; history and reload press one exact
  enabled browser menu item; scrolling prefers a writable AX scrollbar and falls back to a directional
  `AXScrollToVisible` target whose geometry must actually change. The action helper does not use
  `CGEventPost` or arbitrary raw-key injection.
- Each active AX session starts a separate one-shot, listen-only Core Graphics input monitor. Pointer and
  scroll events count only when the topmost window under the event is the exact bound `CGWindowID`; keyboard
  events count only when the browser is frontmost and that exact AX window is focused. The helper emits only
  `ready` or `user_input` and never emits key codes, text or coordinates.
- A matching event immediately invalidates the active Observation and moves the session to
  `paused_for_user`. Observe/action calls then fail before returning a new screenshot or AX snapshot;
  in-flight fallback stops after its current awaited Adapter call. A trusted resume method verifies the same
  surface identity, arms a new monitor and returns a fresh baseline. Unexpected monitor loss marks the
  session failed instead of continuing without takeover protection.
- Electron Main exposes list/pause/resume only through sender-validated, schema-checked IPC. Preload control
  requests accept only an opaque `sessionId`; the React Tool Center renders browser/backend/control-path/state and explicit
  “我来接管” / “恢复自动操作” controls. It receives no URL, title, screenshot, semantic snapshot or page
  element, and `pause`/`resume` remain absent from the model-facing operation union.
- The helper is compiled during local start and Electron packaging, unpacked beside `app.asar`, and checked
  as an executable release artifact on Darwin targets.

The production driver imports only the native AX observe/action/close path. Earlier unused JXA/System
Events observation and action implementations were removed; JXA remains narrowly scoped to default-browser
discovery, window enumeration and navigation of the already verified front window. New-window creation now
prefers an exact browser menu-item AXPress and retains the prior System Events shortcut as a compatibility
fallback; neither path is accepted unless one unique new `CGWindowID` becomes stable.

## Security and failure boundary

- Opening fails before mutation unless Screen Recording, Accessibility trust, the native helper and a
  supported default-browser bundle are available.
- Every observation/action revalidates PID, native window ID and bounds. Semantic action tolerates unrelated
  dynamic page changes but the helper still requires exactly one matching role/name/bounds target. Visual
  fallback additionally requires the same URL, page revision and screenshot digest.
- Password, payment and authentication fields expose no value and force user takeover. The implementation
  does not enumerate cookies, passwords, extensions, history or other tabs/windows.
- Failure during open closes the newly created window. `detach` only releases control. `close` is accepted
  only for the OpenerX-created surface with a fresh observation and returns `closed` only after the exact
  `CGWindowID` is absent for three consecutive polls.
- The smoke runner now exits non-zero on failure and attempts exact-window cleanup before exiting.
- The input-monitor child is stopped on detach, close, host shutdown and resume re-arm. Malformed output,
  startup timeout or post-ready process loss cannot silently leave an active unmonitored session.
- Before and after the final two real-browser runs, the same two pre-existing Chrome window IDs remained and
  no additional test window remained open.
