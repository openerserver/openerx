The registry binds every Session and Observation to backend, control path, application ID, native PID,
native window ID, surface kind/ID, ownership, profile persistence, URL, page revision, viewport, scale and
surface bounds. It emits independent short-lived Observation, semantic snapshot, visual Observation and
element references. References expire at the 30-second boundary and are invalidated by action completion,
navigation, layout/surface change, Bridge/Host disconnect, cancellation, supersession or user takeover.

The dispatcher accepts exactly one typed operation. It attempts a permitted semantic action first, then
native input, then a coordinate tied to the current visual Observation. It revalidates Session and surface
state after each asynchronous Adapter call, so cancellation or user takeover prevents every later fallback.
Audit records contain action/path/result and exact surface identity, but omit text, selected values, file
payloads and screenshot bytes.

## Security and evidence boundary

The registry rejects whole-screen captures and capture inputs whose trusted Adapter has not declared
redaction. It filters sensitive semantic values and never includes operation text or screenshot data in its
audit record. Because BCU-002 has no real capture Adapter, the `redacted=true` field is an attestation, not
pixel-level proof. BCU-003/004 must test actual screenshot masking with visual canaries before either backend
can be enabled.

This checkpoint does not implement or prove:

- system-default browser discovery, Browser Bridge authorization or OS Accessibility input;
- managed Electron Chromium, temporary/persistent Profile behavior or profile clearing;
- Capability Broker policy, Pi ToolDefinition projection, Renderer controls or runtime feature flags;
- a real browser window, signed build, native permission prompt or real website smoke test.
