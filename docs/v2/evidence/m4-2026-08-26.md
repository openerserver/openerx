## File and object boundary

The native chooser runs in Electron Main. App Service receives only the selected paths over its private
privileged command, creates an exact local `FileScope`, canonicalizes every access, and copies bytes into
the profile content-addressed store before parsing. Renderer and Pi receive stable IDs, parsed text and
citations, not arbitrary filesystem access.

PersonalFile/Attachment/Artifact metadata is queued through the existing account revision/cursor sync.
PersonalFile and ArtifactVersion bytes use a separate account-scoped object service. Its transfer intent
is five-minute, one-time and bound to account, device session and device; size and SHA-256 must match.
The dual-replica FILE-08 test proves a PDF attachment and both versions of an Artifact can be opened on
device two while the restored file has no source scope. It also proves sync payloads contain no
`sourceScopeId`, local `objectRef` or fixture path.

The desktop Artifact preview exposes a native “下载 / 另存” action. The user-selected destination is
handled in Main and copied by the Broker; an existing filename receives a suffix and is never silently
overwritten. Renderer never receives the destination path.

## Pi boundary and recovery

Pi remains the only agent harness. M4 registers `openerx_file_list`, `openerx_file_search`,
`openerx_file_read` and `openerx_artifact_write` as Pi-native ToolDefinitions. The tools carry stable IDs
over the private Pi Host/App Service protocol; reads are limited to attached files and writes append an
ArtifactVersion through the controlled store. Raw Pi filesystem built-ins are not registered.

Each Conversation has a persistent Pi `SessionManager`. The registry is atomic and path-confined; a
corrupt registry is rebuilt from Pi session headers. Tests cover host restart, corrupt registry recovery
and compaction while preserving the separate product Conversation/Message truth.

## Real artifact fixtures and visual verification

The committed fixtures are under `tests/v2/fixtures/m4/` and are generated by `scripts/m4/` with the
workspace document runtime. Verification performed for this checkpoint:

- PDF: `pdfinfo` confirms PDF 1.4, A4, two pages and no encryption; Poppler rendered both pages and the
  images were visually inspected.
- DOCX: the document renderer produced two page PNGs and a PDF; both pages were visually inspected after
  correcting bullet layout.
- XLSX: the Data and Summary sheets were rendered to PNG; values, formulas, widths and anomaly spacing
  were inspected.
- PPTX: all six slides were rendered to PNG and a montage; every slide was inspected, and
  `slides_test.py` reported no overflow.

Generated render outputs stay under ignored `tmp/m4-artifact-render/`; the deterministic source
fixtures and generators are versioned.
