## Runtime boundary

Pi remains the only agent harness. Pi Host registers UWA tools and derives every idempotency key from
the product generation and Pi tool-call identity; model-provided input cannot choose the key. App Service
projects Pi activity and blocks on the Broker's permission decision, but it does not plan or reorder tool
steps. The normalized result returns to the same Pi call.

The Broker binds approval to the operation digest and checks capability, resource, action, risk, expiry
and revocation. L4/L5 and Shell execution are per-call. Startup recovery marks interrupted calls/runs
failed, expires pending decisions and revokes temporary Scope. Committed side effects replay from their
stored result rather than running twice.

## Capability adapters

- Web search and image generation use account-authenticated first-party platform endpoints. The client
  consumes normalized sources/artifact IDs and does not invent server results.
- Shell accepts a command plus argv, never a shell command string. CWD real paths must stay under the Pi
  workspace; network is denied unless the approved payload explicitly enables it.
- Browser sessions use a dedicated in-memory Electron partition per session, no preload, `sandbox: true`, context
  isolation and an allowlisted HTTP(S) origin. Upload uses a stable PersonalFile ID resolved to the M4
  controlled content store; Main rejects any path outside that profile CAS. Downloads are re-imported
  into that store and return only a PersonalFile ID. Submit remains separately approved.
- Desktop operations execute in Main. Submit/send/delete/purchase are always L5 per-call operations.
- MCP uses official TypeScript SDK v2 transports. STDIO child lifetime follows the connection; HTTP
  supports Bearer and desktop public-client OAuth Authorization Code + PKCE, safe reconnect and explicit
  credential clearing. The former `client_credentials` implementation is rejected rather than reused.

## Golden boundary

M5 records local evidence for GT-TOOL-01 through GT-TOOL-06 and the non-Skill recovery slice of
GT-TOOL-10. GT-TOOL-07 through GT-TOOL-09 are Skill installation/lifecycle/sync tasks and intentionally
remain M7 gates. M5 does not create placeholder evidence for them.

```bash
node scripts/e2e-tools.mjs
```
