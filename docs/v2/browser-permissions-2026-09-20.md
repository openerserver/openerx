# 浏览器连接和网站权限分层（2026-09-20）

后续共同能力调整见 [自带浏览器与 Chrome 扩展能力统一](browser-managed-parity-2026-09-20.md)。

## 用户行为

设置 → 工具 → 浏览器操作 → 设置：准备扩展、在 Chrome 加载并配对一次。已经加载旧版的用户需要重新准备扩展，并在 `chrome://extensions` 刷新扩展（0.2.0）。

- 连接的是一个 Chrome 扩展所在的配置环境，不是电脑上的所有浏览器，也不是历史浏览记录。当前连接可以发现该环境内普通 HTTP/HTTPS 标签页，复用登录态；不列出无痕或浏览器内部页面。
- 不再要求在扩展弹窗内逐标签授权。任务发现已有标签页后领取控制权，或自动创建新标签页；同时匹配多个页面时必须选择明确的上下文引用。
- 网站权限独立于标签页：本次任务允许、始终允许此网站、允许所有网站、阻止此网站。取消仅拒绝本次请求，不写入阻止列表。
- 默认询问新网站。设置可管理完整域名（不包含协议/路径/端口；子域名分别管理）。HTTP 和 HTTPS、同域名不同端口共用网站规则。阻止规则优先于所有网站和临时授权。
- 已阻止的网站也不会出现在任务的标签页发现列表中。
- “本次任务”在当前执行轮次结束、取消或断开连接后失效；长期网站规则保存在当前应用资料目录。开启所有网站不等于开始控制所有标签页，仍需任务领取标签页。
- 同一窗口内切换标签页不会撤销任务控制。跨站链接、显式导航及 Document 重定向按新网站规则检查；导航后旧观察和元素引用失效。
- 用户输入仍会暂停自动操作，可在设置恢复；停止/任务结束解除控制但不关闭用户已有标签页。断开并清除配对会立即撤销连接、轮换密钥，旧配对码不能继续使用。
- 自动模式有连接时使用该 Chrome；没有连接才创建临时独立浏览器。指定已连接 Chrome 后连接/权限失败，不会静默切换登录环境。

## 实现边界

`BrowserSitePermissions`（主进程网站策略）→ `ChromeExtensionServer`（认证连接、任务意图和上下文）→ 扩展（发现/领取/新建标签、有限 DOM/CDP 动作）→ 原有观察/动作内核（序号、文档身份、旧观察、用户接管检查）。

配对通过固定扩展 Origin、随机密钥和连接 ID 的本地 loopback 通道。新增连接协议能力版本检查，旧扩展不会被误报为支持自动标签页管理。配对端口/密钥以仅当前用户可读写的文件保存，应用及扩展重启后自动重连；不是 Native Messaging 迁移。

模型不获得配对密钥、原始 CDP、任意脚本、浏览器历史或 Cookie 导出接口。允许网站意味着可以读取/操作该站已登录页面，但原有工具审批和敏感输入限制不变。页面文字不能修改网站规则；规则更新只通过受信设置 IPC 或原生权限对话框。

现有 iframe/Shadow DOM 内部语义操作、上传下载、敏感输入限制不变。已观察到的链接/表单新窗口目标归一为受控标签内导航；任意 JavaScript 创建的弹窗不自动领取控制，也不承诺弹窗导航权限隔离。网站策略约束受控页面操作，不是整个 Chrome 的网络防火墙（脚本、图片等子资源不按该规则过滤）。当前一次连接一个扩展环境，不承诺跨浏览器或多个 Chrome 配置并行连接。

## 回归方式

```sh
npm run test:desktop-common
npm run test:e2e:browser:extension --workspace @openerx/desktop
npm run dev:desktop
node apps/desktop/scripts/e2e-browser-settings.mjs
```

设置 E2E 需开发服务就绪，使用临时资料目录；UWA 的脚本位于 `core/apps/desktop/scripts/`，开发服务从外层根目录启动，保留 UWA 品牌与中央账号集成。扩展 E2E 使用临时 Chrome for Testing 资料和本地网页，不操作用户日常 Chrome。可用 `OPENERX_TEST_CHROMIUM` 指定已安装的测试浏览器。

覆盖任务/网站/所有网站规则、阻止优先、取消/撤销、连接密钥轮换、伪造领取拒绝、真实扩展发现/领取/新建、多标签切换、跨站链接/重定向、旧观察、脱敏、用户接管、重启重连，以及真实设置页和 IPC。共同校验同时包含扩展目录，版本品牌差异作为已审查 overlay 保留。
