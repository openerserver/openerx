# V1 用户与场景合同

> 状态：`APPROVED_PRODUCT_SCOPE / IMPLEMENTATION_IN_PROGRESS`
>
> 合同类型：个人客户端用户画像、核心任务与场景优先级

## 1. V1 唯一主用户

`已确定`：V1 只围绕“正在亲自使用客户端完成工作的个人用户”设计。

默认画像：

- 是企业中的普通员工，但以个人身份使用客户端。
- 熟悉聊天软件、浏览器和办公文件，不理解 Agent 基础设施。
- 既有几分钟内完成的问答，也有需要文件和工具的较长任务。
- 希望随时开始，不愿先创建项目、组织或工作流。
- 关心自己的历史是否保存、文件是否安全、工具是否会越权。
- 不希望准备模型 API Key，但希望知道所选模型、Token、实际费用和账户余额。
- 可能在办公 Windows 电脑和个人 macOS 电脑之间继续同一项工作。
- 可能离开电脑，希望从手机查看和引导仍在在线桌面上执行的任务，而不是远程接管整台电脑。

核心 Job Story：

> 当我需要查问题、处理文件或完成一项工作时，我希望像聊天一样直接说明需求，让客户端在获得必要授权后调用合适模型和工具，并把过程、结果和文件都留在同一个可继续的对话中。

## 2. 不进入 V1 的角色

以下角色只属于 `Future Enterprise`：

- 产品负责人。
- 团队负责人或部门管理者。
- 企业管理员、安全审计员和平台运营人员。
- 组织级助手、知识库或审批流程的发布者。

V1 可以保留个人高级设置和诊断，但不能以这些未来角色为页面设计前提。

## 3. 核心场景

### 3.1 SC-CHAT：日常对话与内容处理

用户行为：

- 提问、解释概念、头脑风暴。
- 总结、改写、翻译和调整语气。
- 生成邮件、提纲、计划、文案或代码片段。
- 继续追问、编辑问题、停止或重新生成。

完成标准：

- 打开客户端即可开始，不要求额外配置。
- 首次内容快速流式出现。
- Markdown、表格、代码和复制体验可靠。
- 对话可以重命名、搜索、归档和删除。
- 用户可以清楚判断模型是否仍在生成。

### 3.2 SC-FILE：对话中处理个人文件

用户行为：

- 拖入 PDF、文档、表格、演示文稿、图片或文本文件。
- 针对一个或多个文件提问、比较、总结或提取信息。
- 让系统基于文件生成新文档、表格或 PPT。

完成标准：

- 文件解析状态和失败原因可见。
- 系统只读取用户明确添加或授权的文件。
- 结论可以引用文件名、页码、工作表或数据范围。
- 生成文件可以预览、下载和再次加入对话。
- 原始文件不被静默覆盖。

### 3.3 SC-TOOL：使用工具完成个人工作

用户行为：

- 使用检索、计算、文档生成或其他内置工具。
- 使用 Web 搜索、隔离浏览器、Shell/代码执行或受控桌面操作。
- 根据需要调用个人/工作区 Skill 或本地、远程 MCP 工具。
- 对较长执行查看简化进度，必要时中止。

完成标准：

- 用户知道正在调用什么类型的能力。
- 读取和低风险处理尽量不中断对话。
- 敏感文件、外部写入、Shell、浏览器或桌面控制等动作先确认。
- 工具失败后给出可操作原因，不直接暴露原始堆栈。
- 工具范围达到 [10-codex-capability-baseline.md](10-codex-capability-baseline.md) 的 V1 门禁。

### 3.4 SC-HISTORY：个人历史与上下文复用

用户行为：

- 搜索过去对话、文件和成果。
- 从历史对话继续。
- 把过去生成的文件重新加入当前上下文。
- 清理不再需要的历史和缓存。

完成标准：

- 搜索结果能够回到正确消息或成果。
- 删除和保留行为有明确说明。
- Pi Session/AgentSession 失效不影响历史阅读。
- 同步状态、保存位置、待同步项目和最后同步时间对用户透明。
- 在另一台已登录设备可恢复核心对话、附件云副本和成果。

### 3.5 SC-MODEL：选择平台模型并查看 Token 与费用

用户行为：

- 保持“自动”模型，或从平台提供的模型目录明确选择一个模型。
- 在选择前比较模型能力、速度、上下文限制和当前计价方式。
- 查看当前消息、对话和账户累计 Token、实际费用和抵扣来源。

完成标准：

- 不要求用户配置 Provider 或 API Key。
- 明确选模只影响后续消息，并随对话同步。
- 选择模型、实际模型和任何降级都可追溯。
- 已知 Token 分类正确；上游没有提供的分类明确显示“暂不可得”，不以 0 冒充。
- 每笔实际费用能回到 Token、价格快照、额度/积分/余额扣减和账单记录。

### 3.6 SC-BILLING：查看额度并完成充值和对账

用户行为：

- 查看可用额度、积分、充值余额、即将过期项目和最近费用。
- 在余额不足时创建充值订单，通过正式支付渠道完成支付。
- 返回客户端查看充值结果，再核对一次收费任务和月度账单。
- 在支付中断、重复回调或扣费争议时查看明确状态和支持编号。

完成标准：

- 额度、积分和充值余额不会混成一个无法解释的数字。
- 充值状态以服务端验证结果为准；刷新、重复通知和跨设备打开不会重复入账。
- 收费前可见计价方式和最大可扣金额；实际费用不超过用户接受的上限。
- 消费、退款、冲正和调账均有可追溯流水，余额变化都能由账本解释。
- 账单可以按月份和类型筛选，并下载结构化明细。

### 3.7 SC-SYNC：跨设备继续个人工作

用户行为：

- 在 Windows 或 macOS 登录个人账户。
- 等待历史同步后继续已有对话或打开成果。
- 查看同步失败、冲突、离线写入和删除状态。

完成标准：

- 同一账户的核心历史在支持平台间恢复，不同账户严格隔离。
- 断网期间可读取缓存并排队受支持的修改，恢复网络后幂等同步。
- 冲突不静默覆盖；设备级文件路径、工具授权、Cookie 和密钥不被复制到另一台设备。

### 3.8 SC-REMOTE：从手机监督桌面任务

用户行为：

- 用 iOS/Android 扫描桌面二维码并选择一台在线 Windows/macOS 主机。
- 从手机开始或继续任务，使用 Steer 改变当前方向、用 Queue 排队下一步、用 Stop 终止执行。
- 回复问题、审批仍有效的受限动作，查看 Diff、测试、终端、截图和成果。
- 在主机离线、手机断线或设备丢失后查看准确状态并撤销配对。

完成标准：

- 手机是控制面，Pi、本地工具和文件只在桌面执行；用户不需要理解 Relay 或 Pi Session。
- Queue/Steer 语义明确并直接采用 Pi `followUp()`/`steer()`，重复投递不重复执行或收费。
- 手机审批不扩大桌面既有 Scope，高风险动作按策略回到桌面。
- 主机离线时不谎报已接受，也不会在稍后意外执行过期命令。
- 完整标准见 [15-remote-control-contract.md](15-remote-control-contract.md)。

## 4. 首个纵向闭环

`已确认`：

> 用户打开新对话，上传业务数据表和汇报模板，输入“分析本周异常，生成一页摘要、分析表和六页 PPT”，在对话中查看进度并获得可预览、可下载的成果。

该闭环验证：

- 新对话和流式交互。
- 多文件上传、解析和上下文选择。
- 表格分析和确定性计算。
- Pi AgentSession 与工具调用。
- 长任务进度、停止和恢复。
- 文档、XLSX、PPTX 成果。
- 对话历史和成果再次访问。
- 文件与工具权限。
- 平台模型选择和 Token 使用量展示。
- 费用报价、额度/积分抵扣、余额不足、充值和账单闭环。
- 账户云同步与另一设备恢复。
- 从手机查看执行、Steer/Queue、处理一次审批并审阅成果。

## 5. Future Enterprise 场景

以下不作为 V1 验收任务：

- 负责人查看团队使用和成果。
- 团队共享对话、助手、文件和知识。
- 管理员统一安装连接器或模型。
- 企业审批、预算、审计和策略。
- 组织级身份、数据权限继承和多租户隔离。

## 6. 用户研究假设

V1 实施前需要验证：

1. 用户更希望启动后直接进入聊天，而不是任务 Dashboard。
2. 左侧历史 + 中央对话是主要返回路径。
3. 个人文件/成果库有价值，但不应压过对话主入口。
4. 默认自动模型与平台模型的明确选择可以同时满足普通用户和高级用户。
5. 工具确认需要足够清楚，但不能让每个低风险步骤都打断用户。
6. 用户能理解本地缓存、账户云同步与设备级权限不随账户继承的差别。
7. Token 与实际费用能够帮助用户理解消耗，而不会干扰普通聊天。
8. 普通用户能区分额度、积分和充值余额，并能独立完成充值和账单核对。
9. 用户能理解“手机控制面、桌面执行面”，并能正确区分 Queue 与 Steer。

建议用 5 至 8 名目标用户测试聊天、文件、长任务和手机 Remote 四个核心流程。

## 7. 场景排除规则

V1 不得宣传为已经支持：

- 团队管理、组织治理和产品负责人视图。
- 未授权本地目录的自动扫描。
- 无确认的高风险外部写操作。
- 完整企业知识权限继承。
- 平台目录之外的模型、未通过兼容检查的 Skill/MCP，以及任意企业连接器兼容。
- 无人监督的高影响业务决策。
- 手机端独立执行 Pi/桌面工具、远程桌面、远程唤醒、主机离线执行或从手机新增桌面操作系统权限。
