# V1 个人安全与权限合同

> 状态：`APPROVED_PRODUCT_SCOPE / IMPLEMENTATION_IN_PROGRESS`
>
> 合同类型：个人账户与同步、个人商业账户、本地文件、平台模型、工具授权、Pi Host 隔离、Remote 和删除

## 1. V1 安全原则

1. 模型和 Agent 不是可信边界。
2. 个人客户端不等于默认拥有整台电脑权限。
3. 文件、文件夹、网络、应用控制和 Shell 分别授权。
4. 平台密钥、账户令牌、Cookie 和连接器令牌不得进入聊天或普通日志。
5. 工具能力越强，默认授权范围越小。
6. 未来企业治理不能替代 V1 当前必须具备的个人安全。
7. Token、费用和支付是不同信任域；Pi Host 和客户端都不能成为余额真值。
8. Pi 完整提供 agent harness，但 Pi、模型输出和 Pi 发起的工具调用都不是授权边界；实际设备能力必须经过 V2 Capability and Permission Broker。
9. 手机远程控制只传递可验证的用户决定；Remote Relay、手机和 Pi 都不能替代桌面 Broker 的最终授权判断。

## 1.1 Electron 信任边界

- React Renderer 视为不可信 Web 执行环境，不拥有 Node 能力。
- Preload 只提供最小、类型化 Bridge。
- Electron Main 是桌面权限 Broker，但不直接运行模型和长任务。
- Personal App Service 与 Pi Host 使用独立进程边界；只有 Pi Host 加载 Pi 包。
- 远程网页、Markdown HTML 和模型返回内容不得进入特权上下文。

## 2. 云同步决定与默认数据模式

`已确定`：V1 支持账户云同步，并使用“账户云真值 + 本地受控缓存/离线队列”的混合模式：

- 账户范围的项目元数据/说明/对话归属、对话、消息、分支、附件云副本、成果、模型选择、Skill 安装记录和可同步设置存储在服务端；商业账户数据由专用服务端账本存储。
- 本机保存启动、离线读取、搜索和待同步写入所需缓存。
- 项目目录的绝对路径与 Grant、其他设备权限、浏览器 Cookie、Shell 历史、平台密钥、日志和 Pi 临时目录不进入云同步。
- 不提供完全未登录模式；网络中断时允许读取缓存和排队受支持的内容写入，且不能削弱账户模式的同步和隔离门禁。

不得用模糊文案让用户误以为内容“仅本地”，实际却发送到云服务或远端模型。

## 3. 本地数据

本地缓存和设备数据最低要求：

- 应用数据进入明确的应用目录，不散落到 Pi 包或工具源码目录。
- 数据库和文件权限仅允许当前系统用户访问。
- 账户刷新令牌、Remote 设备私钥和 MCP/OAuth 设备凭证进入系统 Keychain、Secure Enclave、Android Keystore 或等效凭证库；平台上游模型密钥不得下发客户端。
- 缓存、临时文件和 Pi 工作区有明确清理周期。
- 提供导出、清理缓存、删除对话和删除全部个人数据入口。

## 4. 账户与云同步

- 明确认证、会话过期和设备退出机制。
- 服务端按账户隔离项目、对话、文件、成果和事件。
- 传输使用加密通道，静态敏感数据采用适当保护。
- 用户知道哪些内容同步、哪些只在本机。
- 本地清缓存、退出设备和删除云端账户数据是三个不同操作。
- 多设备冲突必须保留版本或请求用户决定。
- 同步操作使用账户、设备、对象 revision 和幂等键校验；客户端时间戳不能直接覆盖云端版本。
- 撤销设备后立即拒绝新的拉取、上传、Remote 连接/命令/事件补读、预签名文件访问、用量/账单查询和充值订单创建。

多租户企业隔离不是 V1 默认范围；一旦 V1 采用共享云服务，账户间隔离立即成为硬性门禁。

## 5. 文件和文件夹权限

- 单文件添加只授权该文件的读取副本或受控句柄。
- 文件夹访问必须显示路径、读/写范围和授权时长。
- Pi Host 和工具不得通过符号链接、相对路径或命令绕过授权根目录。
- 写入默认使用应用输出目录或用户明确选择的位置。
- 原始文件不静默覆盖；覆盖和删除必须确认。
- 从对话移除附件不等于删除个人文件，UI 必须区分。
- 项目只是目录配置来源，不是授权主体；每台设备仍须通过系统目录选择器建立独立 WorkspaceGrant。
- 项目存在多个有效目录时恰有一个主目录；主目录切换与撤销必须在事务中完成，不能出现双主目录或隐式扩大路径。
- 项目目录的主/附加角色、读写范围、来源和当前设备连接状态必须可见；另一设备同步到逻辑占位后保持 fail closed，直到用户重新连接目录。
- 项目目录撤销、过期、设备撤销或路径失效后，下一轮不得继续访问；活动轮次遵循冻结快照、可取消执行与 `outcome_unknown` 恢复合同。

## 6. 工具权限等级

风险等级、操作系统沙箱与审批频率是三个独立维度。风险等级用于审计、展示和远程认证门禁；沙箱决定动作技术上能触达的边界；审批策略决定该动作是自动执行、复用当前对话 Scope，还是逐次确认。不能因为动作是 L2/L3 就机械地每次弹窗，也不能因为无需弹窗就降低其风险记录。

| 等级 | 示例 | 默认策略 |
| --- | --- | --- |
| L0 无副作用 | 计算、格式化、内存文本处理 | 可直接执行 |
| L1 受控读取 | 当前附件、用户选定文件 | 已授权输入内自动执行并记录 |
| L2 扩展读取 | 文件夹、Web 搜索、Browser 页面、屏幕读取 | 第一方 Web/图片与已授权 Browser surface 观察自动；桌面读取按应用 Scope 确认 |
| L3 本地写入 | 工作区 Patch、无外网沙箱 Shell、普通桌面交互 | 已授权读写工作区内自动；桌面交互首次按应用和当前对话确认 |
| L4 外部写入 | 浏览器/桌面发送消息、提交表单、修改远端记录 | 默认逐次确认 |
| L5 高风险执行 | 越出工作区的 Shell、删除、购买、凭证操作 | 严格逐次确认；可按策略禁用 |

默认 `Auto` 语义与 Codex 一致：用户显式授予读写工作区后，该范围内的读取、Patch 和操作系统沙箱
Shell 不再二次询问；Shell 网络只有在工作区授权时单独启用后才可用。Browser 的低风险观察和普通
语义交互可在已授权域名/surface Scope 内执行；首次连接 Browser Bridge、上传、外部提交和高影响
动作按风险逐次确认。系统浏览器首版上传/下载及密码、支付、2FA、CAPTCHA 和安全提示进入用户接管。
Desktop 的截图/普通交互按目标应用建立当前对话 Scope，发送、提交、删除和购买仍逐次确认。只读
MCP 工具和工具发现自动执行；MCP 连接、写入/破坏性调用及清除凭据逐次确认。

“始终允许”必须限定工具、路径/域名、动作类型和有效期，不能成为全局无限授权。

macOS 的屏幕录制/辅助功能权限和 Windows 的屏幕/UI 自动化权限必须由系统授权与 UWA Scope 共同约束；系统已经授权不等于模型可以任意控制所有应用。应用内必须提供当前授权说明和撤销入口。

## 7. Pi Host 隔离

Pi 管理 Agent Loop、Session、上下文压缩、内部重试和工具调用生命周期；这些职责不授权它直接访问设备。复杂 Run 默认要求：

- 独立临时目录。
- 只挂载当前授权输入。
- 不挂载整个 Home、SSH、浏览器 Profile 或全局凭证目录。
- Shell、Pi Host 与 Skill 脚本默认无任意出站网络；需要联网时按工具和目标授权。第一方 Web 搜索与
  Browser Computer-Use 使用各自独立网络策略。
- 系统浏览器仅复用其自身已有账号状态，Host 不读取 Cookie、密码、Token、历史或完整 DOM；托管
  Chromium 使用隔离 Profile。两种后端的远程页面都不获得主 Renderer Preload Bridge 或本地能力。
- Shell 和 Skill 脚本在批准工作目录与资源限制内执行；MCP 子进程不能成为越权代理。
- 限制 CPU、内存、磁盘、进程和执行时间。
- 停止后终止子进程并回收临时资源。
- 输出文件通过类型、大小和基本安全检查后进入成果区。

## 8. 平台模型、用量、费用与凭证

- V1 桌面端不提供 BYOK 或自定义 Provider 配置，上游模型密钥只存在于平台服务端凭证系统。
- 日志、错误提示、同步事件、用量明细和诊断包不包含完整账户令牌、平台密钥或第三方凭证。
- UI 显示平台模型、实际路由、Token、价格版本、费用和抵扣，不显示上游密钥或内部 Provider endpoint。
- UsageRecord、ChargeRecord、额度、积分、余额和账单按账户隔离，客户端只能读取自己的记录。
- 重放、重试和同步恢复不得重复累计同一次模型调用或重复扣费。
- 收费执行前由服务端完成价格冻结和资金预留；Pi Host 只收到可执行/不可执行及本次上限，不获得完整钱包写权限。
- 远端模型会接收哪些文本和文件必须有清晰说明。

### 8.1 支付与账本安全

- Renderer、Electron Main、Pi Host、Skill、MCP 和普通同步 API 都不能提交任意余额或账本分录。
- 充值使用支付服务商托管收银台；远程支付页面无 Preload Bridge、Node、主 Renderer Cookie 或系统凭证。
- 支付服务商密钥、回调验签和退款凭证只存在于服务端密钥系统。
- 回调必须验签、校验订单/金额/币种、限制时间窗、防重放并幂等处理；客户端跳转结果不作为入账依据。
- 已入账流水追加不可变，更正必须冲正；人工调账和额度/积分发放记录权限、原因和审计引用。
- 日志、遥测和诊断包不记录支付密码、银行卡信息、验证码、完整回调载荷或可复用支付令牌。
- 价格配置、支付、退款、账本和余额投影执行职责分离，并通过每日支付/用量对账发现差异。
- 详细边界和发布门禁见 [11-billing-and-commerce-contract.md](11-billing-and-commerce-contract.md)。

## 9. Skill 与 MCP

- 显示来源、版本、声明工具和需要权限。
- 安装与首次使用分开授权。
- 支持禁用、卸载和权限重置。
- 更新后新增权限必须重新确认。
- 未签名或未知来源能力不得伪装成内置可信工具。
- Skill 脚本、引用资源和 MCP 工具使用与内置工具相同的沙箱、网络、文件和审批系统。
- 账户只同步安装记录和非敏感设置；每台设备重新授予本地文件、Shell、浏览器和桌面控制权限。

## 10. Remote Control

- 手机与桌面必须属于同一账户，并通过短时一次性二维码、设备公钥和当前账户 MFA/Passkey 要求完成配对。
- 手机和桌面只建立出站 TLS/WSS；Remote Host Connector 不开放 localhost 或公网监听端口。
- 命令包含主机、配对、设备、会话、revision、单调序列、时效、幂等键和签名；正文及敏感运行详情在已配对设备间端到端加密。
- Relay 只保存路由元数据、短 TTL 密文、游标和回执，不读取 Prompt、Diff、终端、截图、凭证或 Pi 原始事件。
- 推送通知只携带不透明对象 ID 和通用状态，不包含对话正文、本地路径、审批目标或运行内容。
- Remote 审批必须仍为 pending、未过期且未撤销；手机不能扩大主机文件 Scope、网络目标、操作系统权限或创建设备级“始终允许”。
- L3/L4 手机审批要求设备解锁或生物识别；L5 每次重新认证，操作系统权限、密码管理器、支付认证和新文件夹授权必须回到桌面。
- 主机离线、休眠、应用退出或 Remote 关闭时不接受新执行和审批；V1 不提供远程唤醒、离线命令邮箱或云端代跑。
- 配对、命令、审批和撤销审计必须关联控制手机、执行主机和最终 Broker 结果。完整合同见 [15-remote-control-contract.md](15-remote-control-contract.md)。

## 11. 历史、删除与诊断

- 删除对话、文件、成果、缓存和全部数据是不同操作。
- 删除后是否仍存在本地缓存、同步墓碑、备份或保留期副本必须说明。
- 删除对话或账户不能删除法律和财务要求保留的用量、支付和账本证据；保留记录去除不必要内容并向用户说明期限。
- 诊断包默认脱敏，用户可以预览再导出。
- 崩溃报告不自动附带完整对话和附件。
- 历史在用户主动删除前持续保留，删除后进入 30 天回收期；匿名内容遥测默认关闭，脱敏诊断只在用户同意后上传。

## 12. V1 安全门禁

- Pi Host 无法读取未授权本地文件。
- 文件夹 Scope 和符号链接绕过测试通过。
- API Key 不出现在日志、消息、事件和诊断包。
- 高风险工具不会未经确认执行。
- 停止执行后相关子进程和临时权限被回收。
- 本地 API 不能被任意网页或本机低权限调用者直接滥用。
- 两个账户之间的历史、文件、同步事件、Token/费用、额度、积分、余额、订单、账单和预签名对象访问隔离测试通过。
- 被撤销设备不能继续读取、写入或使用旧预签名地址。
- 被撤销或跨账户手机不能连接、补读 Remote 敏感事件、提交命令或批准动作；重复、过期、乱序和篡改命令均安全拒绝。
- Remote 命令不能重复调用 Pi、重复产生工具副作用、UsageRecord 或 ChargeRecord；主机不暴露入站 Remote 端口。
- 推送、Relay 日志和诊断包不包含 Remote 业务正文、Diff、终端、截图、本地路径或审批详情。
- Usage/Charge 去重、缺失 Token 字段、价格快照、账本平衡、支付回调防重放、聚合一致性和跨账户查询测试通过。
- 不存在无账本分录的余额变化、负余额、重复入账或重复扣费。
- `nodeIntegration` 关闭，`contextIsolation` 和 Renderer Sandbox 开启。
- IPC sender、参数、导航、新窗口和外部链接限制测试通过。
- 应用更新包来源和签名校验通过。

## 13. Future Enterprise

未来的组织策略、管理员审计、团队知识权限、SSO 和多租户治理需要独立安全合同。V1 只保留可扩展身份和 Scope 概念，不提前实现企业控制台。
