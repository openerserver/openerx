# V1 验收合同

> 状态：`APPROVED_PRODUCT_SCOPE / IMPLEMENTATION_IN_PROGRESS`
>
> 合同类型：个人聊天客户端、手机 Remote、交互、可靠性、安全和 Pi harness 门禁

## 1. 验收原则

V1 的可用结论必须来自个人用户实际完成聊天、文件和工具任务，不能只以页面存在、接口返回或旧测试通过替代。

## 2. 产品指标

默认 Beta 目标：

| 指标 | 目标 |
| --- | --- |
| 首次开始对话 | 80% 新用户在打开后 30 秒内成功发送第一条消息 |
| 首次成功结果 | 80% 新用户在 3 分钟内获得一个有用结果 |
| 桌面启动 | 在批准的基准机上达到约定冷启动与热启动预算 |
| 日常聊天成功率 | 不低于 95%，排除明确模型内容拒绝 |
| 文件任务成功率 | 不低于 85% |
| 停止成功率 | 不低于 99%，停止后不继续追加可见内容 |
| 历史找回率 | 用户可在 30 秒内找到指定历史对话或成果 |
| 无前置技术配置率 | 不低于 90% |
| 跨设备同步成功率 | 网络正常时核心对象最终同步成功率不低于 99.9% |
| 同步可见延迟 | 95% 小型对话更新在 10 秒内可由另一在线设备看到 |
| Token 记录完整率 | 已完成模型请求 100% 有 UsageRecord 或明确的不可计量状态 |
| 费用记录完整率 | 所有收费 UsageRecord 100% 有唯一 ChargeRecord、价格快照和账本结果 |
| 重复扣费/入账 | 0 |
| 账本平衡率 | 100% 已入账业务事务借贷平衡，余额可由账本重建 |
| 支付入账延迟 | 服务端确认支付后 99% 在 60 秒内完成入账或进入可见异常队列 |
| 未解释对账差异 | 0 个超过批准处理时限的资金差异 |
| 模型选择一致率 | 明确选模请求 100% 记录选择模型与实际模型；无静默替换 |
| 高风险未授权执行 | 0 |
| 未授权本地文件访问 | 0 |
| 跨账户数据访问 | 0 |
| Remote 有效命令最终应用率 | 主机在线且未被策略拒绝时不低于 99.9% |
| Remote 重复执行或副作用 | 0 |
| Remote 跨账户/撤销后控制 | 0 |

以上为已确认验收基线；实施期只能通过有记录的合同变更调整。

## 3. 核心可用性流程

每名测试用户至少完成：

1. 打开客户端并开始新对话。
2. 追问、停止和重新生成。
3. 编辑旧消息并理解结果版本。
4. 上传文件并针对文件提问。
5. 使用一次需要确认的工具。
6. 完成一个长任务并获得文件成果。
7. 离开后返回同一对话。
8. 搜索一条历史消息和一个成果。
9. 从平台目录明确选择模型，并查看本次与累计 Token、价格和费用。
10. 在另一台支持设备登录并继续同一对话、打开同一成果。
11. 安装并显式调用一个测试 Skill，再验证自动触发和卸载。
12. 连接一个测试 MCP，并完成允许、拒绝和断开。
13. 分别完成 Web 搜索、系统默认浏览器/托管 Chromium Computer-Use 和受控 Shell 操作。
14. 删除对话或清理个人数据，并核对本机与云端状态。
15. 查看额度、积分和余额，在余额不足时完成一次充值，再核对消费与月度账单。
16. 使用 iOS/Android Remote Companion 配对在线桌面主机，完成 Start、Steer、Queue、Stop、一次问题回复、一次审批和一次 Diff/测试/Artifact 审阅。

严重失败：

- 用户被带到 Dashboard、项目或治理页面，不知道如何聊天。
- 发送、停止或重试状态不清楚。
- 文件是否上传、解析或被使用不可判断。
- 权限卡无法理解读取/写入范围。
- Pi Host 中断导致历史消息消失。
- 用户无法找到生成成果。
- 同步冲突或失败不可见，或另一设备继承了本地路径/工具权限。
- 明确选择的模型被静默替换，或 Token/费用缺失、重复累计/扣减却无提示。
- 用户无法解释余额变化，充值成功未入账、支付失败却入账，或费用超过接受的上限。
- Skill、MCP、浏览器或 Shell 可以绕过统一权限系统。
- 手机把 Queue/Steer 混为同一动作、主机离线时谎报已接受，或远程命令重复调用 Pi/产生副作用。
- 被撤销或其他账户的手机仍能查看敏感运行详情、控制主机或批准动作。

## 4. 聊天交互门禁

- 消息发送幂等，不产生重复用户消息。
- 流式增量顺序正确，不重复或回退文本。
- 停止后最终状态明确。
- 重新生成和编辑不静默覆盖旧结果。
- Markdown、表格、代码块、链接、引用和复制正确。
- 长对话压缩或截断行为可解释。
- 模型切换只影响后续消息。
- 对话保存明确模型选择，并显示实际执行模型和回退原因。
- 本次 Token、价格和费用详情可折叠查看，不阻塞消息正文。

## 5. 文件与成果门禁

- 支持范围内文件有固定解析测试。
- 不支持、损坏、加密或超大文件有明确错误。
- 文件引用可以定位到正确页、工作表或数据范围。
- 原始文件不被静默修改。
- 生成的 DOCX、XLSX、PPTX、PDF 按批准范围实际打开或渲染验证。
- Artifact 可以下载、再次引用、版本化和从历史找回。
- HTML 预览没有 Preload Bridge 或 Node 能力。
- 文件夹授权、撤销、符号链接和路径穿越测试通过。
- 附件云副本和 Artifact 在另一设备可打开；绝对路径和原设备 Grant 不被同步。

## 5.1 Codex 工具与 Skill 门禁

[10-codex-capability-baseline.md](10-codex-capability-baseline.md) 中 FILE-01 至 FILE-08、TOOL-01 至 TOOL-10、SKILL-01 至 SKILL-10 均为 V1 Release 硬门禁：

- Web 搜索返回可打开来源，并记录搜索活动。
- Browser Computer-Use 的系统默认浏览器与托管 Chromium 后端分别通过确定性语义/Canvas 夹具和
  日期化真实站点烟测；网页位于独立操作面，标准 HTML 不依赖坐标，视觉 fallback 受 Observation
  边界约束，账号/Profile 隔离和用户接管规则可验证。
- 受控桌面操作在 Windows 与 macOS 均能工作，高影响动作逐次确认。
- Shell 绑定授权工作目录，支持流式输出、输入、停止、超时、长进程和退出状态。
- 本地 STDIO 与远程 Streamable HTTP MCP 均通过；Bearer/OAuth、禁用、重连和清除授权可验证。
- Skill 支持标准目录、显式/自动触发、脚本/参考/资产、个人/工作区 Scope、更新权限复核、同步安装记录和卸载。
- 所有工具定义和 Skill 上下文由 Pi 使用，脚本、MCP 和自动触发 Skill 的实际能力统一经过 V2 Capability and Permission Broker；不存在旁路文件、网络、Shell 或桌面权限。

## 5.2 账户同步门禁

- 注册/登录、会话刷新、退出当前设备、退出全部设备和设备撤销通过。
- Conversation、Message、分支、附件云副本、Artifact、模型选择和可同步设置跨 Windows/macOS 恢复。
- 断网内容写入进入离线队列；恢复后幂等同步，不重复消息、文件版本或 Token 记录。
- 额度、积分、余额、费用、支付和账单只读取服务端快照，不进入客户端离线写队列，也不参与内容冲突合并。
- 并发编辑产生可见冲突或确定性合并，不静默覆盖。
- 删除、本地清缓存、退出设备和云端保留期行为分别验证。
- 不同账户、已撤销设备及过期预签名地址均无法访问目标数据。

## 5.3 平台模型、Token 与费用门禁

- 客户端不提供 BYOK、自定义 Provider endpoint 或本地模型配置入口。
- 模型目录能力、状态和限制与服务端一致。
- “自动”和明确选模均可执行；模型不支持当前文件/工具时先提示，不静默切换。
- Token 字段按可获得程度记录；未知显示未知，不写成 0。
- UsageRecord 覆盖成功、失败、停止、重试和缓存命中，并关联选择模型与实际模型。
- 消息、对话、日期、模型和账户聚合结果与原始 Token 记录一致。
- 幂等重放、消息重试和同步重试不重复累计 Token。
- Model Catalog 展示生效价格；执行前创建报价和资金预留，结算使用冻结价格快照。
- ChargeRecord 可回到 UsageRecord、实际模型、计费数量、费率、抵扣和最终费用。
- 停止/失败按实际可收费量结算并释放未用预留；免费请求也产生可解释的零现金扣款记录。

## 5.4 额度、积分、充值与账单门禁

[11-billing-and-commerce-contract.md](11-billing-and-commerce-contract.md) 全部资金不变量为 V1 Release 硬门禁：

- 额度、积分和充值余额分开存储、展示和记账，来源、适用范围与有效期可见。
- 已确认规则为人民币结算、额度按可抵扣金额、最早到期额度→最早到期积分→充值余额、不透支。
- 支付宝和微信支付的订单、托管收银台、服务端查单/验签回调、退款及每日对账通过。
- 客户端跳转、轮询、回调重放、服务重启和跨设备刷新都不会重复入账。
- 所有余额变化都有平衡账本分录；已入账记录不可更新/删除，更正通过冲正。
- 充值成功/失败、支付确认中、余额不足、费用待核算、退款和账单调整都有明确用户状态。
- 首次收费前明确接受版本化收费/退款条款；后续请求只在可见报价和用户单次上限内授权。
- 每笔费用不超过用户接受的最大金额；余额不足时执行前阻止并提供替代路径。
- 月度账单可按消费、充值、退款、冲正和调账核对并下载；账单明确不等于税务发票。
- 积分兑换比例由版本化配置提供；未配置或无效配置时积分抵扣关闭且阻断正式发布，不使用隐含默认值。

## 5.5 Remote Control 门禁

[15-remote-control-contract.md](15-remote-control-contract.md) 是 V1 Release 硬门禁：

- iOS 与 Android 真机均可与 Windows x64、macOS arm64/x64 主机完成同账户二维码配对和撤销。
- 主机、手机仅建立出站 TLS/WSS；扫描和运行时检查均证明桌面没有 Remote 入站监听端口。
- Start 调用 Pi `prompt()`，Steer 调用 `steer()`，Queue 调用 `followUp()`，Stop 调用 `abort()`；Release 依赖图中没有第二套队列、SessionManager 或 harness。
- 主机在线时流式消息、工具状态、问题、审批、Diff、测试、终端、截图和 Artifact 可按游标恢复。
- 主机离线、休眠、应用退出或 Remote 关闭时不接受新执行/审批，不产生稍后意外执行。
- 命令重复、乱序、过期、篡改、旧 revision、多手机竞争和 Relay 重连均给出确定性结果，不重复调用 Pi、工具副作用、UsageRecord 或 ChargeRecord。
- 手机审批不能扩大主机 Scope；L3/L4 需要设备解锁或生物识别，L5 逐次认证，主机限定动作仍只能在桌面完成。
- 推送、Relay 日志和诊断包不包含 Prompt、回答、Diff、终端、截图、路径、审批目标或凭证。
- 被撤销设备、跨账户设备和过期配对不能连接、补读敏感事件、发命令或审批。

## 6. Pi Harness 门禁

发布验证必须使用维护中的 Pi 包和真实配置的模型：

- Pi 是正式构建中唯一的 agent harness；生产源码和 Release 路径不得包含测试 Provider 或固定回答模型。
- Pi 负责 Agent Loop、AgentSession/SessionManager、上下文压缩、内部重试和工具调用生命周期。
- Pi Host Supervisor、WorkItem/ExecutionRun 投影和 Capability Broker 中不存在平行 Agent Loop、步骤规划、Session 管理、压缩、重试或工具调度器。
- Pi Host 的事件合同覆盖消息、工具、权限、压缩、重试、用量和 Session 状态，并有顺序、重放、终态与版本升级契约测试。
- 工具由 Pi 发起并接收结果；Scope、审批、沙箱、系统副作用和审计由 V2 Capability and Permission Broker 执行。
- Remote 的 Queue/Steer/Stop 必须直接使用 Pi `followUp()`/`steer()`/`abort()`，不允许 App Service 或 Relay 模拟这些运行语义。

- 流式聊天。
- 停止和重新生成。
- 多轮继续。
- 文件输入。
- 工具调用和权限回复。
- 长任务离开后继续。
- Pi Host 异常退出后的恢复或明确失败。
- 用量记录和错误归一化。
- 平台 Model Gateway、Token、价格快照、费用预留和结算回写。

缺少凭证而跳过的测试可以存在于普通 CI，但不能计入 Beta 或 V1 通过。

## 7. 可靠性门禁

| 故障 | 必须结果 |
| --- | --- |
| 客户端刷新/重启 | 已完成历史可读，活动任务恢复或明确失败 |
| 流式连接断开 | 按游标补读，不重复消息 |
| App Service 重启 | 已接受消息不丢失 |
| Pi Host 退出 | 不删除历史，保留已有成果；Pi Session 可恢复时恢复，否则明确失败 |
| 文件解析失败 | 不阻塞删除文件或继续纯文本对话 |
| 工具超时 | 有限重试，用户可停止 |
| 重复发送 | 幂等，不产生重复工具副作用 |
| 用户停止 | 子进程和临时权限及时回收 |
| 账户服务暂时不可用 | 已缓存历史可读，写入排队，恢复后幂等同步 |
| 同步冲突 | 两个版本可追溯或按固定规则合并，不静默丢失 |
| Token 记录延迟 | 消息正常完成，用量标记稍后更新，后续可刷新 |
| 费用核算延迟 | 保持已接受的费用上限，显示待核算并自动重试，不重复扣费 |
| Billing Service 不可用 | 不启动新的收费执行；免费且可验证请求可按策略继续 |
| 重复支付回调/查单 | 幂等处理，同一支付只入账一次 |
| 支付成功但入账中断 | 可恢复事务/Saga 自动继续并进入对账异常，不要求用户重复支付 |
| 退款或调账中断 | 原状态可追溯，可幂等恢复，不直接覆盖余额 |
| 账本投影损坏 | 从不可变分录重建余额，禁止以缓存反向覆盖账本 |
| MCP/Skill 崩溃 | 普通聊天和其他工具可继续，权限不扩大 |
| Remote Relay 断开 | 主机继续已接受的 Pi 工作；手机恢复后按游标补读，不重复命令 |
| 主机休眠/离线 | Presence 变为 offline；拒绝新执行和审批，历史只读可用 |
| 多手机竞争 | 按 sessionSequence/baseRevision 接受一个确定顺序，冲突命令刷新后重试 |

## 8. 安全门禁

以下任一失败阻断发布：

- Pi Host 读取未授权文件或文件夹。
- API Key、Cookie 或令牌进入消息、日志或诊断包。
- 高风险工具未经确认执行。
- 权限范围变化后继续复用旧授权。
- 任意网页可以调用本地 App Service 的敏感接口。
- 删除后仍在普通搜索中返回已删除内容。
- 不同账户可以读取彼此的历史、文件、同步事件、用量、余额、支付或账单。
- 已撤销设备仍可使用旧会话或预签名地址访问云数据。
- 模型请求绕过 Platform Model Gateway 或客户端获得上游 Provider 密钥。
- 同一模型调用因重试或同步被重复累计 Token 或费用。
- 客户端、Pi Host、Skill、MCP 或普通同步 API 可以直接修改余额或账本。
- 支付回调未验签/未防重放，或支付凭证进入 Renderer、消息、日志或诊断包。
- 价格变化追溯修改已完成费用、余额出现无分录变化、账本不平或账户被静默透支。
- Remote 主机开放入站端口、Relay 可读敏感正文、推送泄露内容，或命令签名/加密/时效/去重可被绕过。
- 手机扩大桌面 Scope、创建设备级永久授权，或被撤销/跨账户设备仍可控制与审批。

- V1 新代码 lint 零错误。
- 类型检查通过。
- Electron Main、Preload 和 React Renderer 分层测试通过。
- Renderer 不依赖 Node 全局对象，Preload Bridge 类型与实现一致。
- 单元、集成、契约和端到端测试通过。
- 数据迁移在新库和升级样本通过。
- 事件顺序、重复、断线和补读测试通过。
- Pi Host 消息、工具、权限、压缩、重试、用量和 Session 事件翻译契约测试通过。
- 依赖图和代码扫描证明 V2 没有第二套 Agent Loop/Session/compaction/retry/tool-lifecycle 实现，测试 Provider 不进入 Release 构建。
- 工具调用具有幂等和权限测试。
- 支持格式的成果经过渲染验证。
- 云同步 Schema、冲突、删除墓碑、设备撤销和 Token/费用记录契约测试通过。
- 价格精度/舍入、资金预留、复式账本、支付/退款幂等、回调验签、防重放和每日对账测试通过。
- Codex 能力矩阵在 Windows 与 macOS 均有 E2E 证据。
- Remote 命令/事件合同、设备密钥、配对/撤销、iOS/Android 真机和 Windows/macOS 主机组合 E2E 通过。

## 10. 黄金任务门禁

[09-golden-task-catalog.md](09-golden-task-catalog.md) 包含 50 条任务。

已确认标准：

- 50 条均有端到端记录。
