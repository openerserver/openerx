# 公共核心架构与边界

OpenERX 的公共核心面向个人 AI 桌面使用。默认采用用户自己的模型凭据（BYOK），无需平台账户即可使用本地对话、项目、文件、工具、Skill、记忆和自动化。支持范围与限制以 [开发指南](DEVELOPMENT.md) 和 [隐私说明](PRIVACY.md) 为准。

## 进程与数据所有权

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| Electron Renderer / Preload | 界面与类型化调用 | 直接访问文件系统、凭据或任意 IPC |
| Electron Main | 窗口、系统权限、凭据库、目录选择、进程监督 | Agent 推理循环、将密钥传给界面 |
| App Service | 本地业务、持久化、项目、自动化、记忆与同步协调 | 自行授予系统或工具权限 |
| Pi Host | 组合维护中的 Pi AgentSession，投影执行事件 | 第二套 Agent Loop 或产品数据库真值 |
| Capability Broker / Tool SDK | 校验授权范围、操作、风险与执行后端 | 因模型或 Skill 请求而自动扩大权限 |
| Remote Host / Protocol | 可选的通用远程协议与受控桌面连接器 | 独立执行主机或另一套任务运行时 |

Conversation、Message、项目、文件引用及成果由公共业务层持久化，Pi Session 是执行引用。系统凭据、目录授权和绝对路径属于当前设备，不能作为普通同步内容传播。自动化需要桌面后台进程运行；关闭应用或休眠不等于托管调度。

## 公共接口与可选服务

`packages/contracts` 保存接口 Schema，`packages/storage` 维护校验迁移及事务，`packages/file-service` 处理受控文件副本与成果。Skill 通过公共能力边界执行；更新内置内容时需递增版本并更新校验快照。

`services/` 中的身份、同步、模型、用量和账本是可选的平台实现与测试参考，不是开箱即用的生产托管服务。实际部署需要独立配置。通用金额模型、幂等和不可变账本接口不等于特定发行版的商业规则、商户配置或运营承诺。

## 公共与私有发行版

桌面代码只有一套。企业仓库通过 `core` submodule 固定公共提交，通过品牌清单注入外观；移动端实现、企业品牌素材、企业集成、运营方案和内部交付材料在企业仓库维护。公共核心的远程合同与扩展点不要求开源移动应用，也不自动授予企业产品素材的使用权。

具体协议设计见 [技术资料](v2/README.md)，测试边界见 [测试说明](TESTING.md)。修改权限、凭据、存储或进程边界时，需要同时维护合同和对应回归测试。
