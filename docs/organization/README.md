## 1. 目录用途

这个目录收口的是 OpenerX 的 organization 文档簇：它们共同定义组织化协作的前台心智、成员模型、agent console、研发职责位接入方式，以及 member-first 前端重构方向。

这组文档之间互相引用频繁，而且与 `docs/current/` 的现行入口关系紧密。现在整组进入 `docs/organization/` 后，organization 相关材料不再散落在根 `docs/`。

## 3. 阅读边界

1. 如果问题是“组织化协作的对象模型、成员关系、agent console 或 member-first 页面怎么定义”，优先从这个目录开始读。
2. 如果问题是“哪些文档已经经过当前轮次核验并作为现行依据使用”，仍应回到 `docs/current/README.md`。
3. 如果问题已经进入 workflow 阶段模板、审批治理或执行聚合边界，应切到 `docs/workflow/`；如果进入 runtime 或 task-domain 真值边界，则切到对应功能目录。
